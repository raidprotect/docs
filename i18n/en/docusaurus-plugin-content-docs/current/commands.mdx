All RaidProtect commands, grouped by category. Click a command name to access its detailed documentation.

## Prototype legend {#legend}

- `(arg)`: **required** argument.
- `[arg]`: **optional** argument.
- `[--flag]`: optional boolean flag (slash: `flag: true`, message: `--flag`).
- `[--flag=value]`: optional flag with a value.
- `(@member)` / `(#channel)` / `(@&role)`: prefix indicating the expected type.

## ⚙️ Two ways to use a command {#usage}

Common moderation commands exist in two formats: as a slash command, and as a message with a prefix. The others, such as `/sanctions`, `/snipe` or `/audit`, can only be used as slash commands. The [list of message commands](./guides/prefix.md#activated) shows which ones accept a prefix.

### Slash commands: the simplest way {#slash}

Type `/` in a channel, choose the command and **Discord prompts you for each parameter in a dedicated interface** (user picker, channel picker, autocomplete on durations, etc.). It is the recommended default: you don't have to memorize anything.

```
/ban @member reason: scam spam
```

### Message commands: the most complex way {#prefix}

Once [message commands are enabled in `/settings`](./guides/prefix.md), you can also write commands as plain messages (`?ban …`, `?kick …`, etc.). No graphical interface: you have to **know the syntax** (positional arguments, named flags, free-form trailing argument). In return, it's faster on the keyboard for moderators who know the commands well.

#### Positional arguments

Given in the order of the prototype, without a name. These are the main arguments of the command.

```
?ban 123456789012345678
?slowmode 10s
```

#### Named flags (`--name=value`)

For secondary options. Flags can be placed **anywhere** in the command, in any order.

- `--silent` (boolean): simply enables the option.
- `--delete-messages=7d`: passes a value to the option.

```
?ban @member --delete-messages=7d --silent reason for the ban
?tempban @member 1d --silent he did it again
```

#### "Rest" argument (free-form text)

The last argument of certain commands (typically `[reason]`) captures **everything you write after it**, spaces included, without needing quotes.

```
?warn @member you've broken rule 3 of the server again
```
