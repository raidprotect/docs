管理者アカウントがひとつ乗っ取られるだけで、サーバーは数秒で破壊されかねません。だからこそ、メンバーが重要なロールにアクセスするたびに本人確認を行うことが欠かせません。**Authentification Manager** は、Discord に欠けているこの機能を補います。

![RaidProtect Authentication Manager のブログ記事ソーシャルカード](./assets/rp-authentification-manager.webp)

<!--truncate-->

## ❓ 問題点 {#problem}

管理者アカウントが乗っ取られたとします。数秒のうちに、大量の BAN、チャンネルの削除、データの流出が起こります。Discord の 2FA を有効にしていても、マルウェアやフィッシングページで盗まれたトークンがあれば、この保護は簡単に回避されてしまいます。攻撃者はすでにログインしているため、2FA を求められることがないのです。

Discord には、重要な権限を持つロールの背後に実際に誰がいるのかを確認する仕組みがありません。アカウントにアクセスできる人なら誰でも、何にも妨げられることなく全権限で行動できてしまいます。

管理者アカウントの乗っ取りでチャンネルがひとつ削除されるだけでも、すでに被害は大きすぎます。

## 🔐 解決策：Authentication Manager {#solution}

[Authentication Manager](/docs/features/authentication-manager)（AM）を使うと、重要な権限を持つロールは常時付与されるのではなく、追加の認証を経た後にのみ付与されます。自動で期限切れになる一時的なセッションと組み合わせることで、リスクにさらされる時間を大幅に短縮できます。セッションが終わると、ロールは自動で外されます。

たとえ攻撃者が Discord アカウントを盗んでも、サーバーを破壊できる権限は使えません。ロールがそもそも付与されておらず、それを得るには攻撃者が持っていない認証が必要だからです。

## ✨ 含まれる機能 {#features}

### 🛡️ [4 つの認証方法](/docs/features/authentication-manager#methods)

| **方法** | **説明** | **グレード** |
| --- | --- | --- |
| シンプル PIN | 4〜12 桁の通常の入力 | E〜D |
| 強化 PIN（のぞき見対策） | キーの配置がランダムなテンキー、6〜12 桁 | C〜B |
| OTP（2FA） | Google Authenticator、Authy、1Password などによる 6 桁のワンタイムコード | A |
| パスキー（WebAuthn） | 指紋認証、顔認証、または物理キー（YubiKey） | S |

### 🔑 [セキュリティグレード](/docs/features/authentication-manager#grades)

各方法はグレード（E〜S）に対応しています。ロールごとに必要な最低グレードを選べます。内部向けのアクセスなら PIN で十分ですが、管理者ロールにはパスキーを求める、といった使い分けができます。

### ⏱️ [一時的なセッション](/docs/features/authentication-manager#sessions)

ロールはもう常時付与されません。認証のたびに、期間が限られたセッション（最大 8 時間まで設定可能）が開始されます。期限が切れると、ロールは自動で外されます。

### ⚙️ [マネージャーの仕組み](/docs/features/authentication-manager#users-tab)

認証システムには触れさせずに、メンバーに管理者権限を与えられます。マネージャー自身も認証が必要で、自分の上限より下位のロールしか管理できないため、バックドアの作成や権限昇格を防げます。

### 📋 [監査ログとセッション](/docs/features/authentication-manager#logs-tab)

すべての認証、ロールの付与、操作は、ボットに直接記録されます。Discord のログとは異なり、誰も削除できません。乗っ取られた管理者でさえ、痕跡を消すことはできません。

### 🚫 [総当たり攻撃への対策](/docs/features/authentication-manager#auth-security)

5 回失敗すると 1 時間ロック。10 回失敗するとアカウントが完全にリセットされます。
