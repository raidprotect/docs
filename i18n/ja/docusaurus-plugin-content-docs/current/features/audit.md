`/audit` コマンドは、Discord サーバーの設定を分析し、セキュリティ上の弱点を特定します。権限が緩すぎる、認証レベルが不十分、[保護されていない管理者ロール](/ja/learn/least-privilege)などです。そのうえで、ほとんどの問題をワンクリックで修正することを提案します。

次のコマンドを使用します：```/audit```

:::info
このコマンドは、`管理者` 権限を持つメンバー専用です。レポートはあなただけに表示されます（エフェメラルな返信）。
:::

## ❓ 監査の仕組み {#working}

RaidProtect は、サーバーに**100 点満点の総合スコア**を付け、グレード（**S** から **E**）と評価を表示します。評価は、**優秀**（90 以上）、**良好**（70 以上）、**要改善**（40 以上）、**危険**（40 未満）です。

レポートは 3 つのカテゴリーに分かれ、それぞれに独自のスコアがあります。

- **サーバー設定**
- **ロール**
- **チャンネル**

カテゴリーの「**詳細**」ボタンをクリックすると各チェックの結果が表示され、「**戻る**」でレポートに戻ります。「**更新**」ボタンは、変更後に分析をやり直します。

### 実施されるチェック {#checks}

| カテゴリー | チェック |
|---|---|
| サーバー設定 | **認証レベル** |
| サーバー設定 | **不適切なコンテンツのフィルター** |
| サーバー設定 | **モデレーションの二要素認証（2FA）** |
| サーバー設定 | **デフォルトの通知設定** |
| サーバー設定 | **レイド警告** |
| サーバー設定 | **DM Lock（公開サーバー）** * |
| サーバー設定 | **ボットの数** * |
| ロール | **@everyone の権限** |
| ロール | **自動で取得できるロール** |
| ロール | **招待によって付与されるロール** |
| ロール | **管理者ロール** |
| ロール | **管理者権限を持つボット** * |
| チャンネル | **@everyone のチャンネル権限** |
| チャンネル | **冗長なチャンネル権限** |
| チャンネル | **チームロールの発言許可** * |
| チャンネル | **古いウェブフック** * |

`*` が付いたチェックは**参考情報**です。レポートには表示されますが、スコアには影響しません。**DM Lock（公開サーバー）** は、コミュニティサーバーまたは公開サーバーでのみ表示されます。

これらのチェックについて、補足します。

- **自動で取得できるロール**：モデレーターを介さずにメンバーが取得できるロールが対象で、その取得元（Discord のオンボーディング、RaidProtect の[自動ロール](./onboarding.md#autorole)、ブースト、サブスクリプション、連携サービス、リンクされたロール）も表示されます。
- **チームロールの発言許可**：モデレーション権限を持つロールで、一部のチャンネルに、他ですでにカバーされている発言許可（書き込み、発言など）があるものです。これらは残しています。[`/lock`](./channel-lock.md) の間や [DISCON](./discon.md) のレベル 1 で、チームだけが発言できるようにするためです。一覧のロールがすべて本当にチームのロールであることだけ確認してください。そうでない場合、そのロールはロックをすり抜けます。

RaidProtect が正しく動作するために必要な権限が不足している場合は、スコアとは別に専用の警告が表示されます。存在しない権限が必要なチェック（例：ウェブフックの管理）は、未評価として表示されます。

:::info
RaidProtect がサーバーの一部のチャンネルを見られない場合、レポートに「**分析が不完全です**」という案内が表示されます。そのチャンネルは分析されず、スコアは残りの部分のみで計算されます。
:::

## 🔧 ワンクリックで弱点を修正する {#fix}

自動で修正できるチェックには、「**修正する**」ボタンが表示されます。

| チェック | 適用される修正 |
|---|---|
| 認証レベル | サーバーの認証レベルを**中**にします（「中」以上で合格、「低」は警告、「なし」は不合格） |
| 不適切なコンテンツのフィルター | **すべてのメンバー**に対してフィルターを有効にします |
| デフォルトの通知設定 | デフォルトの通知設定を **@メンションのみ**にします |
| @everyone の権限 | @everyone ロールから機密性の高い権限を外します |
| 冗長なチャンネル権限 | 整理するチャンネルの一覧を開き、「**すべて修正**」を実行します |

**管理者ロール**には自動修正はありません。監査は、「**登録する**」または「**すべて登録**」ボタンで、[Authentification Manager](./authentication-manager.mdx) に追加して保護することを提案します。

:::warning
修正を適用するには、RaidProtect に `サーバー管理` と `ロールの管理` の権限が必要です。
:::

### 冗長なチャンネル権限 {#redundant}

チャンネル権限が**冗長**とは、何も変えない権限のことです。サーバーレベルですでに付与されている、チャンネルの @everyone 権限ですでに付与されている、または効果のない拒否のいずれかです。実際に効かせるには複数の場所で変更する必要があり、死角を生みます。

一覧には、チャンネルごとに各権限と冗長である理由が詳しく表示されます。

- チャンネルの「**無視する**」ボタンで、そのチャンネルを一覧、スコア、「**すべて修正**」から外せます。「**無視した項目**」から元に戻せます。
- カテゴリーを修正すると、同期されているチャンネルも修正されます。
- **管理者**ロールの権限は、「**管理者ロールには効果がありません**」に別途表示されます。Discord は無視しますが、そのロールが管理者を失った場合に適用されるため、こちらでは削除しません。

分析では、[`/lock`](./channel-lock.md) や [DISCON](./discon.md) による現在のロックも考慮されます。

## ✅ 意図的な警告を除外する {#ignore}

警告の中には、承知のうえでの選択もあります。信頼できる管理者ロール、理解したうえで `@everyone` に残した権限などです。カテゴリーの詳細にある「**問題なしにする**」ボタンで項目を選び、「**無視する**」で除外できます。

無視した警告はレポートから消え、スコアにも影響しなくなります。無視した項目の一覧（「**無視した項目**」ボタン）はいつでも確認でき、「**元に戻す**」または「**すべて元に戻す**」で、どれでも元に戻せます。

## よくある質問 {#faq}

### 認証レベルが「中」で十分なのはなぜですか？

「中」では、作成から 5 分未満のアカウントがすでに除外され、使い捨てアカウントの大半をブロックできます。そのため「**修正する**」ボタンはこのレベルを適用します。

### 監査が、管理者ロールのチャンネル権限を外さないのはなぜですか？

Discord は、管理者権限を持つロールのチャンネル権限を無視します。そのため別途一覧表示するだけで、外しません。そのロールが管理者を失えば、再び有効になるからです。

### 冗長な権限の分析から、チャンネルを除外できますか？

はい。冗長な権限の一覧で、チャンネルの横にある「**無視する**」をクリックします。スコアに含まれなくなり、無視した項目から元に戻せます。
