モデレーターの作業を楽にするため、RaidProtect には非常に便利なモデレーションコマンドが用意されています。ユーザーの**[BAN](/ja/learn/discord-sanctions)**や**キック**など、Discord の標準機能を直接操作できます。

こうした操作に加えて、RaidProtect は処罰を受けたユーザーに DM で理由を伝え、それを[処罰の履歴](./sanctions.mdx)とサーバーのログにも記録するので、追跡に役立ちます。

:::info
処罰のコマンド（`/ban`、`/kick`、`/mute`、`/jail`、`/warn` など）と、`/nick`、`/clear`、`/slowmode` は、[プレフィックスでも使えます](../guides/prefix)。`/modview`、`/note`、`/snipe`、`/onduty` は使えません。
:::

:::info
処罰のコマンドはすべて、対象に DM で通知しない `[--silent]` オプションに対応しています。通知の DM（キック、ソフトBAN、一時 BAN）には、サーバーへの招待が付いたボタンが含まれます。
:::

## 🔍 メンバーのモデレーションビュー {#modview}

`/modview` コマンドは、メンバーに関する**一元化されたモデレーションビュー**を、1 つの返信にまとめて開きます。

- **直近の処罰**と、「**すべての処罰を表示**」ボタン
- メンバーの内部**モデレーションメモ**。「**編集**」で変更できます（[`/note`](#note)を参照）
- **最後に削除されたメッセージ**と、「**削除されたメッセージをすべて表示（1 時間以内）**」リンク（[`/snipe`](#snipe)を参照）
- **連携アカウント**（サーバーで[複数アカウント](./alt-accounts.md)を利用できる場合）。BAN できるモデレーター向けに「**管理**」ボタンが付きます
- すぐに対応できる「**ユーザーを処罰する**」セレクター

次のコマンドを使用します：```/modview (user)```

`(user)` を、対象のメンションまたは ID に置き換えます。

:::tip
このコマンドは、コンテキストメニューからも使えます。プロフィールを右クリック → **アプリ** → **Modview を開く**。
:::

## 🖱️ コンテキストメニューから処罰する {#context-menu}

スラッシュコマンドのほかに、プロフィールを右クリックして、メンバーを直接処罰できます：**アプリ** → **ユーザーを処罰**。

ウィンドウが開き、次の項目を入力します。
- **処罰の種類**：適用する処罰の種類（必須）。
- **期間**：BAN、タイムアウト、監禁の期間（任意。例：`1d 2h 30m`）。
- **理由**：処罰の理由。
- **サイレント**：処罰を受けた人に DM を送りません。

選べる種類は、各コマンド（`/ban`、`/softban`、`/jail`、`/kick`、`/mute`、`/warn`）に対するあなたの権限によって決まります。Discord の連携サービスの設定も含まれます。監禁は、[Jail ロール](./sanctions.mdx#jail)が設定されている場合にのみ表示されます。

## <Icon src="/img/icons/SanctionsBAN.svg" alt="icon SanctionsBAN" title=":iconSanctionsBAN:"/> ユーザーを BAN する {#ban}

`/ban` コマンドで、ユーザーのサーバーへのアクセスを、永久に、または指定した期間だけ禁止できます。

次のコマンドを使用します：```/ban (user) [duration] [--delete-messages=duration] [--silent] [reason]```

`(user)` を対象のメンションまたは ID に、`[reason]` を処罰の理由に置き換えます。

- `[duration]`：指定した場合、BAN は一時的になります（[`/tempban`](#tempban)と同じ）。
- `[--delete-messages]`：削除する履歴の範囲（例：`1h`、`1d`、`7d`）。Discord の制限により、削除は最大 7 日までです。
- `[--silent]`：対象に DM を送りません。

:::tip
ユーザーがオフラインでも、サーバーにいなくても、[Discord の ID](../guides/id) があれば BAN できます。
:::

### <Icon src="/img/icons/SanctionsBANTemp.svg" alt="icon SanctionsBANTemp" title=":iconSanctionsBANTemp:"/>  ユーザーを一時的に BAN する {#tempban}

`/tempban` コマンドで、ユーザーのサーバーへのアクセスを一時的に禁止できます。

次のコマンドを使用します：```/tempban (user) (duration) [--delete-messages=duration] [--silent] [reason]```

`(user)` を対象のメンションまたは ID に、`(duration)` を BAN の期間に、`[reason]` を処罰の理由に置き換えます。`[--delete-messages]` パラメーターで、メンバーのメッセージ履歴を削除できます（最大 7 日）。

### <Icon src="/img/icons/SanctionsSOFTBAN.svg" alt="icon SanctionsSOFTBAN" title=":iconSanctionsSOFTBAN:"/> ユーザーをソフトBAN する {#softban}

`/softban` コマンドは、メンバーを BAN して、すぐに BAN を解除します。サーバーから永久に追放することなく、**メッセージの履歴を削除**できます。新しい招待があれば、メンバーは戻れます。

次のコマンドを使用します：```/softban (user) [--delete-messages=duration] [--silent] [reason]```

`(user)` を対象のメンションまたは ID に、`[reason]` を処罰の理由に置き換えます。`--delete-messages` パラメーターで、削除するメッセージの範囲を選べます。

:::tip
ソフトBAN は、**乗っ取られたアカウント**に特に適しています。スパムを一掃してアカウントを解放し、持ち主がアカウントを安全にした後には、永久に追放することにはなりません。
:::

### <Icon src="/img/icons/SanctionsUNBAN.svg" alt="icon SanctionsUNBAN" title=":iconSanctionsUNBAN:"/> ユーザーの BAN を解除する {#unban}

`/unban` コマンドで、以前に BAN したユーザーの BAN を解除し、再びサーバーに参加できるようにします。

次のコマンドを使用します：```/unban (user) [--silent] [reason]```

`(user)` を対象の ID に、`[reason]` を BAN 解除の理由に置き換えます。

## <Icon src="/img/icons/SanctionsKICK.svg" alt="icon SanctionsKICK" title=":iconSanctionsKICK:" /> ユーザーをキックする {#kick}

`/kick` コマンドで、BAN せずにメンバーをサーバーから追放できます。有効な招待があれば、ユーザーは再びサーバーに参加できます。

次のコマンドを使用します：```/kick (user) [--silent] [reason]```

`(user)` を対象のメンションまたは ID に、`[reason]` を処罰の理由に置き換えます。

## <Icon src="/img/icons/SanctionsTIMEOUT.svg" alt="icon SanctionsTIMEOUT" title=":iconSanctionsTIMEOUT:" /> ユーザーをミュートする（タイムアウト） {#timeout}

`/mute` コマンドで、メンバーがサーバーで行える操作を一時的に制限できます。この間、メンバーはメッセージの送信、リアクション、ボイスチャンネルへの参加、他のメンバーへの DM の送信ができなくなります。

次のコマンドを使用します：```/mute (user) (duration) [--force-timeout] [--silent] [reason]```

`(user)` を対象のメンションまたは ID に、`(duration)` をミュートの期間（例：`10m`、`1h`、`1d`）に、`[reason]` を処罰の理由に置き換えます。

:::tip
`[--force-timeout]` オプション（プレフィックスでは別名 `ft`）を使うと、しきい値のルールを無視し、ミュートロールが設定されていても Discord のタイムアウトを強制できます。その場合、期間は 28 日を超えられません。

`/settings` の「**モデレーション**」タブ、「**処罰**」、「**ミュート**」の行で、[ミュートロール](./sanctions.mdx#mute)と[ミュートのしきい値](./sanctions.mdx#mute-threshold)を設定できます。設定したしきい値を超えると、ボットは Discord のタイムアウトの代わりにミュートロールを自動で適用し、28 日を超える期間が可能になります。
:::

### <Icon src="/img/icons/SanctionsUNTIMEOUT.svg" alt="icon SanctionsUNTIMEOUT" title=":iconSanctionsUNTIMEOUT:" /> ユーザーのミュートを解除する {#untimeout}

`/unmute` コマンドで、タイムアウト中のメンバーの制限を直ちに解除し、サーバーでのあらゆる操作を再び行えるようにします。

次のコマンドを使用します：```/unmute (user) [--silent] [reason]```

`(user)` を対象のメンションまたは ID に、`[reason]` をタイムアウト解除の理由に置き換えます。

## <Icon src="/img/icons/SanctionsJAIL.svg" alt="icon SanctionsJAIL" title=":iconSanctionsJAIL:" /> ユーザーを監禁する {#jail}

`/jail` コマンドで、制限付きのロールを付与してメンバーを隔離できます。Jail は BAN の代替手段として用意されています。メンバーは完全に追放される代わりに、非常に限られたサーバーへのアクセスを維持します。

次のコマンドを使用します：```/jail (user) [--silent] [reason]```

`(user)` を対象のメンションまたは ID に、`[reason]` を処罰の理由に置き換えます。

:::warning
このコマンドを使う前に、`/settings` で [Jail ロール](./sanctions.mdx#jail)を設定する必要があります。自動のモジュールは、Jail ロールが未設定の場合、タイムアウトに切り替わります。
:::

### <Icon src="/img/icons/SanctionsJAILTemp.svg" alt="icon SanctionsJAILTemp" title=":iconSanctionsJAILTemp:" /> ユーザーを一時的に監禁する {#tempjail}

`/tempjail` コマンドで、メンバーを指定した期間だけ一時的に監禁できます。

次のコマンドを使用します：```/tempjail (user) (duration) [--silent] [reason]```

`(user)` を対象のメンションまたは ID に、`(duration)` を監禁の期間に、`[reason]` を処罰の理由に置き換えます。

### <Icon src="/img/icons/SanctionsUNJAIL.svg" alt="icon SanctionsUNJAIL" title=":iconSanctionsUNJAIL:" /> ユーザーを解放する {#unjail}

`/unjail` コマンドで、メンバーから Jail ロールを外し、通常のサーバーアクセスを取り戻させます。

次のコマンドを使用します：```/unjail (user) [--silent] [reason]```

`(user)` を対象のメンションまたは ID に、`[reason]` を解放の理由に置き換えます。

## <Icon src="/img/icons/SanctionsWARN.svg" alt="icon SanctionsWARN" title=":iconSanctionsWARN:" /> ユーザーに警告する {#warn}

`/warn` コマンドで、ボット経由の DM を使って、メンバーに正式に警告できます。

次のコマンドを使用します：```/warn (user) [--silent] [reason]```

`(user)` を対象のメンションまたは ID に、`[reason]` を警告の理由に置き換えます。

## 📝 モデレーションメモ {#note}

`/note` コマンドで、[`/modview`](#modview) を経由せずに、メンバーの**内部モデレーションメモ**を追加または編集できます。メモはモデレーターにだけ見えます。

次のコマンドを使用します：```/note (user)```

`(user)` を対象のメンションまたは ID に置き換えます。ウィンドウが開き、最大 300 文字でメモを入力または編集します。メモの追加、変更、削除は、[モデレーションログ](#logs)に記録されます。

## 🏷️ メンバーのニックネームを変更する {#nick}

`/nick` コマンドで、サーバーでのメンバーのニックネームを変更したり、リセットしたりできます。

次のコマンドを使用します：```/nick (user) [pseudo]```

`(user)` を対象のメンションまたは ID に置き換えます。`[pseudo]` パラメーターは、適用する新しいニックネームです（最大 32 文字）。省略すると、メンバーのニックネームがリセットされます。

:::info
このコマンドには Discord の**ニックネームの管理**権限が必要で、[プレフィックスコマンド](../guides/prefix)では別名 `nickname`、`rename`、`setnick` でも使えます。変更はサーバーのログに記録されます。
:::

## 🧹 メッセージをまとめて削除する {#clear}

`/clear` コマンドで、テキストチャンネル内のメッセージを指定した数だけすばやく削除できます。ユーザーを指定すると、そのユーザーのメッセージだけを削除できます。

次のコマンドを使用します：```/clear (amount) [user]```

`(amount)` を削除したいメッセージ数（2〜100）に置き換えます。`[user]` にメンションまたは ID を指定すると、チャンネル内のそのユーザーのメッセージだけが対象になります。プレフィックスでは、別名 `clean` でも使えます。

## 🕒 チャンネルでスローモードを有効にする {#slowmode}

`/slowmode` コマンドで、チャンネルのスローモードを有効にしたり変更したりして、ユーザーが送信するメッセージの頻度を制限できます。

次のコマンドを使用します：```/slowmode (delay) [duration] [channel] [reason]```

- `(delay)` を、メッセージ間の希望する間隔に置き換えます（例：`5s`、`1m`、`10m`、`1h`、最大 6 時間。`0` で無効）。
- `[duration]` を追加すると、その時間が過ぎた後にスローモードが自動で無効になります（例：`30m`、`2h`）。
- コマンドを入力したチャンネル以外にスローモードを適用したい場合は、`[channel]` を追加します。
- `[reason]` を追加すると理由を指定でき、サーバーのログに記録されます。

## 🕵️ 削除されたメッセージを取得する {#snipe}

`/snipe` コマンドは、チャンネルで**直近 1 時間に削除されたメッセージ**を、新しいものから古いものへ、ページごとに表示します。

次のコマンドを使用します：```/snipe [user] [--channel=#channel]```

- 引数なし：現在のチャンネルで削除されたメッセージを表示します。
- `[user]` を指定：そのユーザーの削除されたメッセージだけを表示します。
- `[--channel]` を指定：コマンドを入力したチャンネル以外のチャンネルを検索します。

返信から、メッセージの**投稿者を処罰**できます。返信はあなたにだけ見えます。

:::warning
`/snipe` で確認できるのは、RaidProtect が 1 時間メモリに保持しているメッセージだけです。メッセージが保持されるのは、「**メッセージのキャッシュ**」が有効な場合（`/settings`、「**ユーティリティ**」タブ、既定では無効）、または[スパム対策](./anti-spam.mdx)や[通報](./reports.md)が有効な場合で、その場合は自動的に有効になります。それ以外の場合、コマンドは削除されたメッセージが見つからないと返信します。
:::

メッセージのキャッシュを有効にするには：

1. [`/settings` コマンド](../setup.md#settings)を実行します。
2. 「**ユーティリティ**」タブを開きます。
3. 「**メッセージのキャッシュ**」の横にある「**有効化**」をクリックします。

:::info
これらのメッセージは 1 時間メモリに保持され、データベースには書き込まれません。`/privacy` コマンドで、RaidProtect がサーバーについて保持している内容を確認できます。
:::

## 🟢 勤務中ロール {#onduty}

**勤務中ロール**を使うと、モデレーターが対応可能であることを示せます。`/onduty` コマンドで、各自が勤務中または勤務外になり、設定したロールが付与または外されます。

次のコマンドを使用します：```/onduty```

返信はあなたにだけ見えます。同じ効果は、[運営パネル（`/display staff`）](./display.mdx#staff)の「**勤務中**」ボタンでも得られます。

### 勤務中ロールを設定する {#onduty-config}

1. [`/settings` コマンド](../setup.md#settings)を実行します。
2. 「**ユーティリティ**」タブを開きます。
3. 「**勤務中ロール**」の横にある「**設定**」をクリックします。
4. セレクターで既存のロールを選ぶか、「**代わりに作成する**」をクリックします（権限を一切持たない `勤務中` ロールが作成されます）。

<Settings start="onduty" />

:::warning
勤務中ロールは、モデレーターが自分で取得するものなので、機密性の高い権限を持ってはいけません。管理者、サーバー管理、ロールの管理、チャンネルの管理、ウェブフックの管理、メッセージの管理、スレッドの管理、表現の管理、イベントの管理、メンバーのキック、メンバーのBAN のいずれかを持つロールは拒否されます。RaidProtect にも、勤務中ロールより上に配置されたロールと、**ロールの管理**の権限が必要です。
:::

## 📋 モデレーションログ {#logs}

既定では、モデレーションログは RaidProtect の全般のログチャンネルに送信されます。専用のログチャンネルを設定すると、モデレーション操作を他のログと分けられます。

1. [`/settings` コマンド](../setup.md#settings)を実行します。
2. 「**モデレーション**」タブを開きます。
3. 「**ログ**」の横にある「**設定**」をクリックします。
4. 「**モデレーション**」セレクターで、モデレーションログを送るチャンネルを選ぶか、「**代わりに作成する**」ボタンを使います。

<Settings start="logs" />

「**ログ**」画面には、「**全般**」「**モデレーション**」「**キャプチャ**」の 3 つのチャンネルがまとまっています。「**モデレーション**」または「**キャプチャ**」を空欄にすると、そのログは全般のチャンネルに送られます。「**受動的なモデレーションログ**」の切り替えで、ボットを介さずに行われた操作も RaidProtect が記録するかどうかを選べます。

## よくある質問 {#faq}

### /snipe でメッセージが見つからないのはなぜですか？

RaidProtect がメッセージをメモリに保持するのは、`/settings` の「**ユーティリティ**」タブでメッセージのキャッシュが有効な場合、またはスパム対策や通報が有効な場合だけです。確認できるのは直近 1 時間のみです。

### /onduty を使うには、どの権限が必要ですか？

既定では、**メッセージの管理**権限です。Discord の連携サービスで調整できます。まず管理者が、`/settings` の「**ユーティリティ**」タブで勤務中ロールを設定する必要があります。

### サーバーにいないユーザーを BAN できますか？

はい、`/ban` と[Discord の ID](../guides/id) で可能です。
