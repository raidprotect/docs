RaidProtect の **Authentification Manager**（AM）は、最も機密性の高い Discord ロールへのアクセスを、確かな本人確認で守ります。パスキー（WebAuthn）、PIN コード、OTP により、メンバーは認証を済ませた後にだけ、限られた時間だけ[機密性の高いロール](/ja/learn/least-privilege)を取得できます。Discord 上では、このモジュールは「**認証マネージャー**」という名前で表示されます。

## ❓ Authentification Manager の仕組み {#working}

Authentification Manager は、**保護されたロール**と**一時的なセッション**で成り立っています。管理者が AM でロールを保護すると、次のようになります。

1. その Discord ロールは常時付与されなくなり、取得するには認証が必要になります。
2. 許可されたメンバーは、`/auth` コマンド（または[運営パネル](./display.mdx#staff)の「**ロールを取得**」ボタン）で認証します。
3. ロールに設定された期間の**一時的なセッション**が作成されます。
4. セッションの期限が切れると、ロールは自動的に外されます。

:::info
各メンバーは、認証する前に、まず `/auth-profile` で**認証プロフィール**を作成する必要があります。
:::

セッション中のメンバーの Discord 上の操作（BAN、メッセージの削除、ピン留め、チャンネルの変更など）は、その対象とともに AM のジャーナルに記録されます。保護されたロールで何が行われたかを把握できます。

## 🔐 セキュリティグレード {#grades}

認証方法ごとに**セキュリティグレード**が付きます。保護されたロールごとに最低グレードが定められており、メンバーはそれに到達する必要があります。

| **グレード**                                                                   | **条件**                         |
| --------------------------------------------------------------------------- | ------------------------------------- |
| <Icon src="/img/icons/RankS.svg" alt="icon RankS" title=":securityRankS:"/> | 登録済みのパスキーが 1 つ以上      |
| <Icon src="/img/icons/RankA.svg" alt="icon RankA" title=":securityRankA:"/> | OTP（2FA）コードが有効                 |
| <Icon src="/img/icons/RankB.svg" alt="icon RankB" title=":securityRankB:"/> | 8 桁以上の強化 PIN    |
| <Icon src="/img/icons/RankC.svg" alt="icon RankC" title=":securityRankC:"/> | 6 桁以上の強化 PIN    |
| <Icon src="/img/icons/RankD.svg" alt="icon RankD" title=":securityRankD:"/> | 6 桁以上のシンプル PIN      |
| <Icon src="/img/icons/RankE.svg" alt="icon RankE" title=":securityRankE:"/> | 4 桁以上のシンプル PIN      |

:::tip
設定した認証方法のうち、最も高いグレードが自動的に採用されます。たとえば、シンプル PIN（グレード D）とパスキー（グレード S）がある場合、グレードは **S** になります。
:::

## 🛡️ 認証方法 {#methods}

<SeparatedBox>
<Tabs>
<TabItem value="pin" label="PIN" default>

PIN コードは最も簡単な方法です。2 つのモードがあります。

- **シンプル PIN**：ウィンドウでの通常の入力（4〜12 桁）。
- **強化 PIN**：入力のたびにキーの位置が入れ替わるテンキー（6〜12 桁）。後ろからのぞき見されても、第三者にコードを推測されにくくなります。

:::warning
単純すぎる PIN は拒否されます。同じ数字の繰り返し、昇順または降順の並び、よくあるパターンなどです。
:::

</TabItem>
<TabItem value="otp" label="OTP（2FA コード）">

OTP は、TOTP（Time-based One-Time Password）標準を使い、[Google Authenticator](https://play.google.com/store/apps/details?id=com.google.android.apps.authenticator2)、[Authy](https://authy.com/)、[1Password](https://1password.com/)、[Dashlane](https://www.dashlane.com/)、[Bitwarden](https://bitwarden.com/) などの認証アプリに対応しています。

- 30 秒ごとに更新される 6 桁のコード。

</TabItem>
<TabItem value="passkey" label="パスキー（WebAuthn）">

パスキーは最も高いセキュリティレベル（グレード S）を提供します。認証はブラウザで、次のいずれかを使って行います。

- **指紋認証**または**顔認証**（Touch ID、Face ID、Windows Hello）。
- **物理セキュリティキー**（YubiKey など）。

パスキーを使うと、Discord の言語で外部リンクがブラウザで開きます。確認が完了すると、ロールが付与されます。

</TabItem>
</Tabs>
</SeparatedBox>

## 👤 認証プロフィール（`/auth-profile`） {#auth-profile}

`/auth-profile` コマンドは、あなた個人の認証プロフィールを管理します。どのサーバーでも、DM でも使え、プロフィールはどこでも同じです。

<Settings start="authProfile" />

### 初回の利用 {#onboarding}

初めて使うときは、グレード、一時的なセッション、認証方法を紹介するウェルカム画面が表示されます。「**続ける**」をクリックして、最初の認証方法を設定します。

### 認証方法の管理 {#manage-methods}

プロフィールから、次の操作ができます。

- **PIN コード**（シンプルまたは強化）の追加、変更、削除。
- QR コードまたはシークレットキーによる**2FA コード**（OTP）の有効化、再生成、削除。
- 登録ページからの**パスキー**の追加、または削除。各パスキーには、デバイス名と最終使用日が表示されます。
- パスキーの**名前の変更**：「**追加**」の横にある「**パスキーを編集**」ボタンで、パスキーの一覧と新しい名前（例：`MacBook`、`iPhone`、`YubiKey`）を入力するウィンドウが開きます。名前の変更は監査ログに記録されます。

すでに認証方法がある場合は、別の方法を追加または変更する前に、認証が求められます。プロフィールの下部には、現在のグレードと、1 つ上げるために追加すべき方法が表示されます。

:::info
認証方法を削除すると、グレードが下がることがあります。その場合、より高いグレードを要求するロールへのアクセスは無効になります。
:::

### 有効なセッション {#profile-sessions}

有効なセッションと有効期限は、各サーバーの [`/auth`](#sessions) コマンドのパネルに表示されます。

### 監査ログ {#profile-audit}

プロフィールには、アカウントで行われた直近 3 件の操作が表示されます。「**すべてのログを表示**」ボタンで、ページ分けされた全ログが、該当するサーバーとともに開きます。

### アカウントのリセット {#reset}

「**認証方法を忘れた**」ボタンは、アカウントを完全にリセットします。この操作では、次のことが行われます。

- すべての認証方法（PIN、2FA、パスキー）が削除されます。
- すべてのサーバーで、保護されたロールへのアクセスが無効になります。
- すべてを再設定する必要があります。

:::danger
この操作は元に戻せません。すべてのアクセスが直ちに取り消されます。
:::

## 🔑 認証する（`/auth`） {#auth}

`/auth` コマンドで認証すると、保護されたロールを取得できます。

次のコマンドを使用します：```/auth [role]```

### 認証の流れ {#auth-flow}

1. サーバーで `/auth` コマンドを実行するか、運営パネルの「**ロールを取得**」をクリックします。
2. メニューに、利用できるロールが、必要なグレードとセッション時間とともに表示されます。
3. ロールを 1 つまたは複数（最大 10）選びます。最も厳しいロールの水準で 1 回認証すれば、すべてのロールが開きます。
4. ロールのグレードに到達する認証方法の中から、1 つ選びます。
5. 確認を行います（PIN、OTP、またはパスキー）。
6. 成功すると、Discord ロールが付与され、ロールごとにセッションが作成されます。セッションは Authentification Manager のログに記録されます。

:::info
メニューに表示されるのは、ステータスが**有効**で割り当てられているロールだけです。
:::

### セッションの管理 {#sessions}

`/auth` パネルには、有効なセッションが一覧表示されます。各セッションで、次の操作ができます。

- **セッションを延長**：もう一度認証すると、セッションの期間が最初からやり直しになります。
- **セッションを終了**：セッションは直ちに取り消され、Discord ロールが外されます。

### セキュリティ {#auth-security}

- **警告**：失敗が 3 回に達すると、警告メッセージが表示されます。
- **ロック**：5 回失敗すると、アカウントが 1 時間ロックされます。
- **リセット**：10 回失敗すると、アカウントがリセットされ、すべてのアクセスが取り消されます。

## ⚙️ サーバーの設定 {#auth-settings}

Authentification Manager の設定パネルは、2 通りの方法で開けます。

1. [`/settings` コマンド](../setup.md#settings)を実行します。
2. 「**保護**」タブを開きます。
3. 「**認証マネージャー**」の横にある「**設定**」をクリックします。

パネルがダッシュボードの代わりに表示され、「**戻る**」ボタンで保護タブに戻れます。同じパネルを開く `/auth-settings` コマンドを直接使うこともできます。

<Settings start="auth" />

:::info
`/auth-settings` コマンドは、既定では管理者専用です。管理者でないマネージャーに使わせるには、**サーバー設定 > 連携サービス > RaidProtect** でそのマネージャーに許可してください。
:::

### 権限 {#permissions}

| **ロール**        | **アクセス**                                                                 |
| --------------- | ------------------------------------------------------------------------- |
| オーナー    | 完全なアクセス                                                             |
| 管理者  | 完全なアクセス（管理者権限が AM で保護されたロール由来の場合を除く） |
| マネージャー    | 制限付きのアクセス：認証が必要で、自分より下位のロールとユーザーだけを管理でき、サーバーの設定は変更できません |

#### マネージャーの認証 {#manager-auth}

オーナーでも管理者でもないマネージャーは、パネルを開くたびに認証する必要があります。**マネージャーの最低グレード**に到達する方法が提示されます。「**PIN で認証する**」「**OTP で認証する**」「**パスキーで認証する**」です。強化 PIN は、キーがシャッフルされるテンキーで入力します。

`/auth` と同じ保護が適用されます。3 回の失敗で警告、5 回の失敗で 1 時間のロック、10 回の失敗でアカウントのリセットです。

### サーバーの設定項目 {#server-settings}

「**サーバー設定**」の横にある「**編集**」をクリックすると、「**サーバーの認証設定**」ウィンドウが開きます。

- **デフォルトのセッション時間**：新しいロールに提案される期間。`30m`、`2h`、`1d` の形式で指定します。無料版は最大 8 時間、[Premium](/ja/premium) 版は最大 24 時間。既定：10 分。
- **デフォルトの最低グレード**：新しいロールに提案されるグレード。既定：A。
- **マネージャーの最低グレード**：マネージャーがパネルを開くために到達すべきグレード。既定：A。
- **Webhook の URL（空欄にすると削除）**：AM のログを受け取る Discord のウェブフック（任意）。Discord のウェブフックの URL のみ使えます。

マネージャーは、これらの設定を変更できません。

### ロールタブ {#roles-tab}

ロールタブには、保護されたロールが、グレード、セッション時間、ユーザー数とともに一覧表示されます。タブの下の「**最近のセッション**」ブロックには最新のセッションが表示され、「**すべて表示**」ですべてのセッションの一覧が開きます。

:::info
**上限：** 無料版は 3 ロール、[Premium](/ja/premium) 版は 10 ロール。無効なロールも、スロットを使用します。
:::

#### ロールを追加する {#add-role}

1. Authentification Manager のパネルを開きます（[上記](#auth-settings)を参照）。
2. 「**ロール**」タブで、「**追加**」をクリックします。
3. 保護する **Discord ロール**を選びます。
4. **最低セキュリティグレード**を選びます。
5. **セッション時間**を指定します。
6. **登録方式**を選びます（下記参照）。
7. すでにそのロールを持っているメンバーが検出されます。選択を調整して、「**招待を送信**」（または「**スキップ**」）をクリックします。

選ばれた各メンバーは、グレードが足りていればステータス**有効**で、足りなければ**招待済み**でロールに紐づけられます。後者の場合、`/auth-profile` の設定を促す DM が届きます。

<SettingsModal name="authAddRole" />

連携サービスが管理しているロール、Discord のオンボーディングで使われているロール、RaidProtect のロールより上位またはあなたのロールより上位のロール、すでに保護されているロールは拒否されます。

##### 登録方式 {#strategies}

| **方式** | **効果** |
|---|---|
| 「**このロールをそのまま使用する**」 | 選んだロールが、そのまま保護されたロールになります。既定の選択です。 |
| 「**権限用のロールを別に作成する**」 | 選んだロールのすぐ下に、元の権限を持つ `🔑 <ロール名>` ロールを作成し、元のロールの権限を空にします。元のロールは色と表示を常に保ち、保護されるのは新しいロールです。 |

:::tip
ロールがメンバー一覧で**別枠表示**されている場合は、「**権限用のロールを別に作成する**」を選んでください。メンバーは表示されるロールを常に維持でき、機密性の高い権限は認証済みのセッション中にだけ付与されます。

ロールを別に作成した場合、表示用のロールが持つチャンネルのモデレーション権限も `🔑` ロールに移ります。管理者ロールでは、「**セッション外もすべてのチャンネルを表示**」オプションで、セッション外でも表示用のロールがすべてのチャンネルを見られるようにできます。このオプションがない場合、管理者権限なしでは何も見えなくなります。
:::

#### `/audit` から管理者ロールを保護する {#audit-bulk}

[監査](./audit.md)の管理者ロールのチェックには、「**すべて登録**」があります。まだ保護されていない管理者ロールをまとめて保護できます。1 回につき最大 5 ロールまでで、空きスロットの範囲内です。表示されるのは、RaidProtect より下かつあなたの最上位のロールより下にあるロールだけです。

#### ロールを編集する {#edit-role}

ロールの行の「**編集**」をクリックしてロールの詳細（最低グレード、セッション時間、割り当てられたユーザー）を開き、さらに「**編集**」をクリックすると、最低グレードとセッション時間を変更できます。

#### ロールを有効化／無効化する {#toggle-role}

ロールの詳細で「**無効化**」を押すと、ロールを削除せずに一時停止します。このロールのセッションは新たに作成されなくなります。進行中のセッションは取り消され、該当するメンバーから Discord ロールが外されます。「**有効化**」で再開できます。スロットの範囲内に限ります。

#### ロールを削除する {#delete-role}

「**削除**」は、そのロールを Authentification Manager から完全に取り除き、ユーザーの割り当てもすべて削除します。確認が求められます。

### ユーザータブ {#users-tab}

ユーザータブには、保護されたロールに 1 つ以上紐づけられたメンバーが、グレード、ロール数、マネージャーかどうかとともに一覧表示されます。

:::info
**上限：** 無料版は 20 ユーザー、[Premium](/ja/premium) 版は 50 ユーザー。
:::

#### ユーザーを追加する {#add-user}

1. 「**ユーザー**」タブを開きます。
2. 「**追加**」をクリックします。
3. **ユーザー**と、割り当てる**認証ロール**を選びます。

メンバーには DM が届きます。グレードが足りていればすぐにロールを使えます。足りない場合は、十分なグレードの認証方法を設定するよう案内されます。

:::info
スパムを防ぐため、招待には制限があります。ブロックされた招待は、後でメンバーの詳細から再送できます。
:::

#### ユーザーの詳細とステータス {#member-status}

「**管理**」をクリックすると、メンバーの詳細が開きます。グレード、ID、マネージャーかどうか、各ロールとそのステータスです。ロールのセレクターで、ロールを追加したり外したりできます。

| **ステータス**  | **説明**                                                   |
| ----------- | ----------------------------------------------------------------- |
| 招待済み      | メンバーは追加されたが、グレードがまだ足りない（プロフィールの設定が必要） |
| 承認待ち  | 承認待ち：「**承認**」をクリックします            |
| 有効       | メンバーは認証してロールを取得できる                |
| 無効   | アクセスが停止中：「**復元**」をクリックして戻します |

#### マネージャーに昇格する {#promote-manager}

「**マネージャーに昇格**」は、マネージャーの最低グレードに到達していることを条件に、メンバーに設定パネルへのアクセスを与えます。マネージャーは、自分より下位のユーザーとロールを管理します。「**マネージャーを解除**」で、このアクセスが外されます。

#### ユーザーを削除する {#delete-user}

「**ユーザーを削除**」は、サーバーのすべての保護されたロールからメンバーを外します。確認が求められます。

### ログタブ {#logs-tab}

ログタブには、Authentification Manager のジャーナルが、ページ分けされて表示されます。付与、延長、取り消されたセッション、設定の変更などです。目のアイコンのボタンで、エントリの詳細（ユーザー、操作、種類、日時、ロール、対象）が開きます。ログは、設定したウェブフックにも送信されます。

### セッション {#sessions-tab}

専用のタブはありません。ロールタブの「**最近のセッション**」ブロックに最新のセッションが表示され、「**すべて表示**」でサーバーのすべてのセッションが、ステータス（有効、期限切れ、取り消し済み）とともに開きます。「**表示**」でセッションの詳細と最近の操作を確認できます。

### オンボーディングの保護 {#onboarding-protection}

保護されたロールが Discord のオンボーディングの質問に追加された場合、質問から自動で取り除き、ログに記録します。そうしないと、参加者の誰もが認証なしでロールを取得できてしまうためです。

### Premium の終了 {#premium-end}

[Premium](/ja/premium) の契約が終了すると、3 を超える有効なロールは自動で無効になり（古いものが保持されます）、8 時間を超えるセッション時間は 8 時間に引き下げられます。

## よくある質問 {#faq}

### どの認証方法を使えますか？

PIN コード（シンプルまたは強化）、OTP（TOTP 標準の 2FA コード）、パスキー（WebAuthn）の 3 つです。パスキーが最も高いセキュリティレベル（グレード S）を提供します。

### Authentification Manager はどこで設定しますか？

`/settings` の「保護」タブで、「認証マネージャー」の横にある「設定」をクリックするか、`/auth-settings` コマンドを直接使います。

### セッションの期限が切れるとどうなりますか？

保護されたロールがメンバーから自動で外されます。再び取得するには、`/auth` で認証し直すか、期限が切れる前にセッションを延長する必要があります。

### 認証方法を忘れた場合は？

`/auth-profile` のプロフィールにある「認証方法を忘れた」ボタンで、アカウントが完全にリセットされます。すべての方法が削除され、アクセスが取り消されます。この操作は元に戻せず、すべてを設定し直す必要があります。

### Authentification Manager で、いくつのロールを保護できますか？

無料版では 3 ロール、Premium 版では 10 ロールで、ユーザーはそれぞれ 20 人、50 人までです。セッションは、無料版で最長 8 時間、Premium 版で最長 24 時間です。

### マネージャーは、すべてを変更できますか？

いいえ。マネージャーはパネルを開くたびに認証する必要があり、自分より下位のロールとユーザーだけを管理でき、サーバーの設定は変更できません。
