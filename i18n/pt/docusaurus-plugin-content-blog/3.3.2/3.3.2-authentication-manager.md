Uma conta admin comprometida, e seu servidor pode ser destruído em segundos. Verificar a identidade dos membros sempre que eles precisam acessar um cargo sensível se torna indispensável. O **Authentication Manager** preenche essa verdadeira lacuna do Discord.

![RaidProtect Authentication Manager blog post social card](../../../en/docusaurus-plugin-content-blog/3.3.2/assets/rp-authentification-manager.webp)

<!--truncate-->

## ❓ O problema {#problem}

Uma conta admin é comprometida. Em segundos: banimentos em massa, canais excluídos, dados expostos. Mesmo com o 2FA do Discord ativado, um token roubado por malware ou uma página de phishing basta para contornar essa proteção: o atacante já está conectado, o 2FA nunca é pedido a ele.

O Discord não oferece nenhum mecanismo para verificar quem está realmente por trás de um cargo com permissões sensíveis. Qualquer pessoa com acesso à conta pode agir com plenos poderes, sem que nada a impeça.

Um único canal excluído pelo hack de uma conta admin já é demais.

## 🔐 A solução: Authentication Manager {#solution}

Com o [Authentication Manager](/docs/features/authentication-manager) (AM), os cargos com permissões sensíveis não são mais atribuídos permanentemente — eles são atribuídos apenas após uma camada adicional de autenticação. Combinado com sessões temporárias que expiram automaticamente, a janela de exposição é drasticamente reduzida: os cargos são removidos automaticamente no final da sessão.

Mesmo que um atacante roube uma conta Discord, ele não pode usar as permissões destrutivas do servidor: o cargo simplesmente não está lá, e obtê-lo requer uma autenticação que ele não possui.

## ✨ O que está incluído {#features}

### 🛡️ [4 métodos de autenticação](/docs/features/authentication-manager#methods)

| **Método** | **Descrição** | **Grau** |
| --- | --- | --- |
| PIN simples | Entrada clássica de 4 a 12 dígitos | E a D |
| PIN anti-espionagem | Teclado numérico com disposição aleatória, de 6 a 12 dígitos | C a B |
| OTP (2FA) | Código temporário de 6 dígitos via Google Authenticator, Authy, 1Password... | A |
| Passkey (WebAuthn) | Impressão digital, reconhecimento facial ou chave física (YubiKey) | S |

### 🔑 [Graus de segurança](/docs/features/authentication-manager#grades)

Cada método corresponde a um grau (E a S). Você escolhe o grau mínimo exigido por cargo: um acesso interno pode se contentar com um PIN, um cargo admin exigirá uma passkey.

### ⏱️ [Sessões temporárias](/docs/features/authentication-manager#sessions)

Os cargos não são mais permanentes. Cada autenticação abre uma sessão de duração limitada (configurável até 8 horas). Ao expirar, o cargo é removido automaticamente.

### ⚙️ [Sistema de managers](/docs/features/authentication-manager#users-tab)

Conceda permissões de admin a um membro sem dar a ele acesso ao sistema de autenticação. Os managers precisam se autenticar e só podem gerenciar cargos inferiores ao seu teto, impedindo a criação de backdoors e a escalada de privilégios.

### 📋 [Logs de auditoria e sessões](/docs/features/authentication-manager#logs-tab)

Cada autenticação, atribuição de cargo e ação é registrada diretamente no bot. Ao contrário dos logs do Discord, ninguém pode excluí-los: nem mesmo um admin comprometido consegue apagar seus rastros.

### 🚫 [Proteção anti força bruta](/docs/features/authentication-manager#auth-security)

5 falhas: bloqueio de uma hora. 10 falhas: reinicialização completa da conta.
