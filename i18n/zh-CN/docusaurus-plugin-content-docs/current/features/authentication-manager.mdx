RaidProtect 的 **Authentification Manager**（AM）通过真正的身份验证来保护对您最敏感的 Discord 角色的访问。借助 Passkey（WebAuthn）、PIN 码和 OTP，成员只有在通过身份验证后才能获得[敏感角色](/zh-CN/learn/least-privilege)，而且仅限一段有限的时间。在 Discord 中，该模块显示的名称为“**身份验证管理器**”。

## ❓ Authentification Manager 如何运作？ {#working}

Authentification Manager 基于**受保护的角色**和**临时会话**。当管理员用 AM 保护某个角色时：

1. 该 Discord 角色不再被永久授予：必须通过身份验证才能获得。
2. 获授权的成员使用 `/auth` 命令（或[工作人员面板](./display.mdx#staff)上的“**获取角色**”按钮）进行身份验证。
3. 系统会按该角色设定的时长创建一个**临时会话**。
4. 会话到期时，我们会自动移除该角色。

:::info
每位成员必须先通过 `/auth-profile` 创建自己的**身份验证档案**，才能进行身份验证。
:::

会话期间，成员的 Discord 操作（封禁、删除消息、置顶、修改频道等）会连同其目标一并记录在 AM 的日志中：您可以清楚地知道每个受保护的角色都做了什么。

## 🔐 安全级别 {#grades}

每种身份验证方式都对应一个**安全级别**。每个受保护的角色都要求成员达到最低级别。

| **级别**                                                                   | **条件**                         |
| --------------------------------------------------------------------------- | ------------------------------------- |
| <Icon src="/img/icons/RankS.svg" alt="icon RankS" title=":securityRankS:"/> | 至少已注册一个 Passkey      |
| <Icon src="/img/icons/RankA.svg" alt="icon RankA" title=":securityRankA:"/> | 已启用 OTP（2FA）验证码                 |
| <Icon src="/img/icons/RankB.svg" alt="icon RankB" title=":securityRankB:"/> | 8 位或以上的增强 PIN    |
| <Icon src="/img/icons/RankC.svg" alt="icon RankC" title=":securityRankC:"/> | 6 位或以上的增强 PIN    |
| <Icon src="/img/icons/RankD.svg" alt="icon RankD" title=":securityRankD:"/> | 6 位或以上的普通 PIN      |
| <Icon src="/img/icons/RankE.svg" alt="icon RankE" title=":securityRankE:"/> | 4 位或以上的普通 PIN      |

:::tip
系统会自动采用您已配置的各种方式中最高的级别。例如，如果您有一个普通 PIN（D 级）和一个 Passkey（S 级），您的级别就是 **S**。
:::

## 🛡️ 身份验证方式 {#methods}

<SeparatedBox>
<Tabs>
<TabItem value="pin" label="PIN" default>

PIN 码是最简单的方式。提供两种模式：

- **普通 PIN**：在窗口中常规输入（4 至 12 位数字）。
- **增强 PIN**：每次输入时按键位置都会变化的数字键盘（6 至 12 位数字），防止他人在旁偷看就猜出您的密码。

:::warning
过于简单的 PIN 会被拒绝：重复的数字、递增或递减的序列，以及常见的组合。
:::

</TabItem>
<TabItem value="otp" label="OTP（2FA 验证码）">

OTP 采用 TOTP（基于时间的一次性密码）标准，兼容各类身份验证应用，例如 [Google Authenticator](https://play.google.com/store/apps/details?id=com.google.android.apps.authenticator2)、[Authy](https://authy.com/)、[1Password](https://1password.com/)、[Dashlane](https://www.dashlane.com/) 或 [Bitwarden](https://bitwarden.com/)。

- 6 位数验证码，每 30 秒更新一次。

</TabItem>
<TabItem value="passkey" label="Passkey（WebAuthn）">

Passkey 提供最高的安全级别（S 级）。身份验证在浏览器中通过以下方式完成：

- **指纹**或**面部识别**（Touch ID、Face ID、Windows Hello）。
- **实体安全密钥**（YubiKey 等）。

使用 Passkey 时，会在浏览器中打开一个外部链接，语言与您的 Discord 一致。验证通过后，角色就会授予给您。

</TabItem>
</Tabs>
</SeparatedBox>

## 👤 身份验证档案（`/auth-profile`） {#auth-profile}

`/auth-profile` 命令用于管理您的个人身份验证档案。它可在任何服务器和私信中使用，且您的档案在所有地方都是同一个。

<Settings start="authProfile" />

### 首次使用 {#onboarding}

首次使用时，会显示一个欢迎界面，介绍安全级别、临时会话和各种方式。点击“**继续**”来设置您的第一种方式。

### 管理身份验证方式 {#manage-methods}

在您的档案中，您可以：

- 添加、更改或删除 **PIN 码**（普通或增强）。
- 通过二维码或密钥启用 **2FA 验证码**（OTP），也可重新生成或删除。
- 在注册页面添加 **Passkey**，或删除其中一个。每个 Passkey 都会显示设备名称及最近使用日期。

如果您已经有一种方式，在添加或修改其他方式之前，我们会要求您先通过身份验证。档案底部会显示您的级别，以及要再上一个台阶需要添加的方式。

:::info
删除某种方式可能会降低您的级别。此时，您对要求更高级别的角色的访问权限将被停用。
:::

### 活动会话 {#profile-sessions}

您的活动会话及其到期时间，显示在各服务器上 [`/auth`](#sessions) 命令的面板中。

### 审计日志 {#profile-audit}

您的档案会显示在您账号上执行的最近 3 项操作。“**查看完整日志**”按钮会打开分页的完整日志，并注明涉及的服务器。

### 重置账号 {#reset}

“**我忘记了验证方式**”按钮会彻底重置您的账号。此操作会：

- 删除您所有的身份验证方式（PIN、2FA、Passkey）；
- 停用您在所有服务器上对受保护角色的访问权限；
- 要求您重新配置一切。

:::danger
此操作不可撤销。您所有的访问权限都会被立即撤销。
:::

## 🔑 身份验证（`/auth`） {#auth}

`/auth` 命令用于验证身份以获取受保护的角色。

使用命令：```/auth [role]```

### 身份验证流程 {#auth-flow}

1. 在服务器上使用 `/auth` 命令，或在工作人员面板中点击“**获取角色**”。
2. 菜单会显示可用的角色及其所需级别和会话时长。
3. 选择一个角色。
4. 在达到该角色级别要求的方式中选择一种身份验证方式。
5. 完成验证（PIN、OTP 或 Passkey）。
6. 验证成功后，我们会授予您该 Discord 角色并创建一个会话。

:::info
只有您被分配且状态为**已启用**的角色才会出现在菜单中。
:::

### 管理会话 {#sessions}

`/auth` 面板会列出您的活动会话。对于每个会话，您可以：

- **延长会话**：再次验证身份，以重新获得完整的时长。
- **结束会话**：会话会被立即撤销，Discord 角色也会被移除。

### 安全性 {#auth-security}

- **警告**：失败达到 3 次时，会出现警告消息。
- **锁定**：失败 5 次后，您的账号将被锁定 1 小时。
- **重置**：失败 10 次后，您的账号将被重置，所有访问权限都会被撤销。

## ⚙️ 服务器配置 {#auth-settings}

Authentification Manager 的配置面板有两种打开方式：

1. 使用 [`/settings` 命令](../setup.md#settings)。
2. 打开“**防护**”选项卡。
3. 点击“**身份验证管理器**”旁边的“**配置**”。

面板随后会取代控制面板，并带有“**返回**”按钮，可返回“防护”选项卡。您也可以直接使用 `/auth-settings` 命令，它会打开同一个面板。

<Settings start="auth" />

:::info
`/auth-settings` 命令默认仅限管理员使用。若要让非管理员的管理者也能使用，请在**服务器设置 > 整合 > RaidProtect** 中为其授权。
:::

### 权限 {#permissions}

| **角色**        | **访问权限**                                                                 |
| --------------- | ------------------------------------------------------------------------- |
| 所有者    | 完全访问                                                             |
| 管理员  | 完全访问（管理员权限来自受 AM 保护的角色时除外） |
| 管理者    | 受限访问：必须通过身份验证，只能管理位于其下的角色和用户，不能修改服务器配置 |

#### 管理者的身份验证 {#manager-auth}

既不是所有者也不是管理员的管理者，每次打开面板都必须通过身份验证。我们会向其提供达到**管理者最低级别**的方式：“**使用 PIN 验证身份**”、“**使用 OTP 验证身份**”或“**使用 Passkey 验证身份**”。增强 PIN 需在按键打乱的数字键盘上输入。

适用与 `/auth` 相同的保护措施：失败 3 次起发出警告，失败 5 次锁定一小时，失败 10 次重置账号。

### 服务器设置 {#server-settings}

点击“**服务器设置**”旁边的“**编辑**”，打开“**服务器身份验证配置**”窗口：

- **默认会话时长**：新角色的建议时长，格式为 `30m`、`2h` 或 `1d`。免费版最长 8 小时，[Premium](/zh-CN/premium) 版最长 24 小时。默认值：10 分钟。
- **默认最低级别**：新角色的建议级别。默认值：A。
- **管理者最低级别**：管理者打开面板必须达到的级别。默认值：A。
- **Webhook URL（留空以清除）**：接收 AM 日志的 Discord Webhook（可选）。仅接受 Discord Webhook 的 URL。

管理者不能修改这些设置。

### “角色”选项卡 {#roles-tab}

“角色”选项卡会列出您受保护的角色，以及它们的级别、会话时长和用户数量。在选项卡下方，“**最近的会话**”区块会显示最新的一个会话，“**查看全部**”则打开所有会话的列表。

:::info
**上限：** 免费版 3 个角色，[Premium](/zh-CN/premium) 版 10 个角色。已停用的角色仍然占用一个位置。
:::

#### 添加角色 {#add-role}

1. 打开 Authentification Manager 的面板（参见[上文](#auth-settings)）。
2. 在“**角色**”选项卡中，点击“**添加**”。
3. 选择要保护的 **Discord 角色**。
4. 选择**最低安全级别**。
5. 填写**会话时长**。
6. 选择一种**接入策略**（见下文）。
7. 我们会检测已拥有该角色的成员：调整所选成员，然后点击“**发送邀请**”（或“**跳过**”）。

每位被选中的成员都会与该角色关联：如果其级别足够，则状态为**已启用**，否则为**已邀请**：此时他会收到一条私信，邀请他去设置 `/auth-profile`。

<SettingsModal name="authAddRole" />

我们会拒绝由集成管理的角色、用于 Discord 新成员引导的角色、位于 RaidProtect 角色之上或您自己角色之上的角色，以及已受保护的角色。

##### 接入策略 {#strategies}

| **策略** | **效果** |
|---|---|
| “**直接使用此角色**” | 所选角色直接成为受保护的角色。这是默认选择。 |
| “**创建独立的权限角色**” | 我们会在所选角色的正下方创建一个 `🔑 <角色名称>` 角色，带有原有的权限，并清空原角色的权限。原角色始终保留其颜色和显示，受保护的则是新角色。 |

:::tip
如果您的角色在成员列表中是**单独显示**的，请选择“**创建独立的权限角色**”：您的成员始终保留可见的角色，而敏感权限只在通过身份验证的会话期间授予。
:::

#### 通过 `/audit` 保护管理员角色 {#audit-bulk}

[审计](./audit.md)中对管理员角色的检查提供“**全部接入**”：您可以一次性保护尚未受保护的管理员角色，每批最多 5 个角色，且以您的空闲位置为限。只会提供位于 RaidProtect 之下和您最高角色之下的角色。

#### 编辑角色 {#edit-role}

在角色所在行点击“**编辑**”以打开其详情页（最低级别、会话时长、已分配的用户），再点击“**编辑**”以更改最低级别和会话时长。

#### 启用 / 停用角色 {#toggle-role}

在角色详情页中，“**停用**”会暂停该角色而不删除它：不再为其创建任何会话。进行中的会话会被撤销，相关成员的 Discord 角色也会被移除。“**启用**”则让它恢复使用，以您的位置数量为限。

#### 删除角色 {#delete-role}

“**删除**”会将该角色从 Authentification Manager 中永久移除，同时删除所有用户分配。系统会要求您确认。

### “用户”选项卡 {#users-tab}

“用户”选项卡会列出至少关联了一个受保护角色的成员，以及他们的级别、角色数量和管理者状态。

:::info
**上限：** 免费版 20 名用户，[Premium](/zh-CN/premium) 版 50 名用户。
:::

#### 添加用户 {#add-user}

1. 打开“**用户**”选项卡。
2. 点击“**添加**”。
3. 选择要为其分配的**用户**和**身份验证角色**。

该成员会收到一条私信：如果其级别足够，他可以立即使用该角色，否则会被邀请设置一种级别足够的方式。

:::info
邀请的发送受到限制，以防止刷屏。被拦下的邀请可稍后在成员的详情页重新发送。
:::

#### 用户详情页与状态 {#member-status}

点击“**管理**”可打开成员的详情页：他的级别、ID、是否为管理者，以及他的每个角色及其状态。角色选择器可用于添加或移除角色。

| **状态**  | **说明**                                                   |
| ----------- | ----------------------------------------------------------------- |
| 已邀请      | 成员已被添加，但其级别尚不足够（需设置档案） |
| 等待中  | 等待批准：点击“**批准**”            |
| 已启用       | 成员可以通过身份验证获得该角色                |
| 已停用   | 访问已被暂停：点击“**恢复**”可重新启用 |

#### 设为管理者 {#promote-manager}

“**设为管理者**”会让成员获得配置面板的访问权限，前提是他达到管理者最低级别。管理者管理位于其下的用户和角色。“**移除管理者**”则撤销其该项访问权限。

#### 删除用户 {#delete-user}

“**删除用户**”会将该成员从服务器上所有受保护的角色中移除。系统会要求您确认。

### “日志”选项卡 {#logs-tab}

“日志”选项卡会分页显示 Authentification Manager 的日志：授予、延长或撤销的会话、配置变更等。眼睛形状的按钮会打开某条记录的详情（用户、操作、类型、日期、角色和目标）。日志同时也会发送到已配置的 Webhook。

### 会话 {#sessions-tab}

没有专门的选项卡：“角色”选项卡中的“**最近的会话**”区块显示最新的会话，“**查看全部**”会打开服务器所有会话的列表及其状态（有效、已过期、已撤销）。“**查看**”会显示某个会话的详情及其最近的操作。

### 新成员引导保护 {#onboarding-protection}

如果受保护的角色被添加到 Discord 新成员引导的问题中，我们会自动将其从该问题中移除并记录到日志中：否则，任何新成员都可能不经身份验证就获得该角色。

### Premium 到期 {#premium-end}

[Premium](/zh-CN/premium) 订阅结束时，超出 3 个的已启用角色会被自动停用（保留最早的），超过 8 小时的会话时长会被调整为 8 小时。

## 常见问题 {#faq}

### 有哪些身份验证方式？

共有三种方式：PIN 码（普通或增强）、OTP（符合 TOTP 标准的 2FA 验证码）和 Passkey（WebAuthn）。Passkey 提供最高的安全级别（S 级）。

### 在哪里配置 Authentification Manager？

在 `/settings` 的“防护”选项卡中，点击“身份验证管理器”旁边的“配置”，或直接使用 `/auth-settings` 命令。

### 会话到期时会发生什么？

我们会自动移除该成员的受保护角色。他需要用 `/auth` 重新验证身份才能再次获得，或在会话到期之前延长会话。

### 如果我忘记了验证方式怎么办？

在您的 `/auth-profile` 档案中，“我忘记了验证方式”按钮会彻底重置您的账号：所有方式都会被删除，访问权限也会被撤销。此操作不可撤销，需要完全重新配置。

### 可以用 Authentification Manager 保护多少个角色？

免费版可保护 3 个角色，Premium 版可保护 10 个角色，对应的用户数量分别为 20 名和 50 名。会话时长在免费版最长 8 小时，在 Premium 版最长 24 小时。

### 管理者可以修改所有内容吗？

不可以。管理者每次打开面板都必须通过身份验证，只能管理位于其下的角色和用户，且不能修改服务器配置。
