RaidProtect 的举报系统让您的社区只需点击几下，就能通过右键点击、专用按钮或 `/report` 命令，向管理员反馈任何可疑的消息或成员。它可以配置，以便让您的团队更高效地处理举报。

## ❓ 举报是如何运作的？ {#working}
成员可以通过 4 种主要方式举报内容。

1. **右键点击消息**
成员可以在他认为违反规则的消息上点击右键，选择 **`应用`**，然后点击 **`举报消息`**。随后会打开一个窗口，让他说明举报的原因。

2. **右键点击用户资料**
同样，成员可以在他认为有问题的用户资料上点击右键，选择 **`应用`**，然后点击 **`举报用户`**。随后会打开一个窗口，让他说明举报的对象（头像、用户名、简介、语音活动、私信活动）以及原因。

3. **信息面板上的按钮**
如果在[信息面板（`/display public`）](./display.mdx)上启用了“举报”功能，面板下方会直接提供“**举报成员**”按钮，让成员可以快速举报用户。

4. **斜杠命令**
成员还可以在服务器的任何频道中通过 **`/report`** 命令举报用户。

使用命令：```/report (member)```

将 `(member)` 替换为所需的用户。随后在窗口中填写原因，与右键点击用户资料时相同。

:::info
启用举报也会启用[消息缓存](./moderation.mdx#snipe)：RaidProtect 会在内存中保留一小时的消息，以便把被举报的内容附加到警报中。
:::

## 🚩 配置举报 {#config}

举报会发送到一个**举报频道**。如果您没有选择，它们会发送到您的通用日志频道。所有设置都在同一个界面中：

1. 使用 [`/settings` 命令](../setup.md#settings)。
2. 打开“**管理**”选项卡。
3. 点击“**举报**”旁边的“**配置**”。
4. 点击界面标题右侧的“**启用**”，打开举报系统。

<Settings start="reports" />

### 配置频道 {#config-channel}

1. 使用 [`/settings` 命令](../setup.md#settings)。
2. 打开“**管理**”选项卡。
3. 点击“**举报**”旁边的“**配置**”。
4. 点击“**接收举报**”旁边的“**编辑**”。
5. 在窗口中选择所需的频道（_例如：#举报 或 #reports_），或勾选“**为我创建频道**”，由 RaidProtect 创建一个私密的 `举报` 频道。

如果您没有选择任何频道，或选择的是日志频道，举报会沿用您的通用日志频道。

<SettingsModal name="reportChannel" />

### 配置通知角色 {#config-role}

1. 使用 [`/settings` 命令](../setup.md#settings)。
2. 打开“**管理**”选项卡。
3. 点击“**举报**”旁边的“**配置**”。
4. 点击“**通知角色**”旁边的“**编辑**”。
5. 在窗口中选择所需的角色（_例如：@管理员 或 @举报通知_），或勾选“**其他提及**”：`@everyone`、`@here` 或“**为我创建角色**”（RaidProtect 会创建 `新举报` 角色）。

未配置角色时，会提及 `@here`。

<SettingsModal name="reportRole" />

:::warning
该频道应仅供管理员使用，以确保举报得到妥善处理。
:::

### 举报分组 {#group}

“**分组**”开关决定针对同一成员的多个举报如何呈现：

- **已启用** *（默认）*：针对同一成员的举报会合并到同一条警报中。
- **已停用**：每个举报都会创建各自独立的警报。

在“举报”界面中点击“**分组**”旁边的“**启用**”或“**停用**”。

<a id="config-notify"></a>

### 举报者通知 {#notify}

“**举报者通知**”旁边的“**编辑**”按钮会打开一个窗口，您可以在其中选择，在举报被处理后，发起举报的成员会通过私信收到什么：

| 级别 | 效果 |
|---|---|
| **已停用** | 举报者不会收到任何通知。 |
| **仅告知已处理** *（默认）* | 告知举报者其举报已被处理。 |
| **附带处理结果** | 告知举报已被接受还是被拒绝。 |
| **附带管理人员** | 同时告知是哪位管理员处理了该举报。 |

即使举报被与其他举报合并，举报者每个举报也只会收到一条消息。

### 信任角色 <span className="badge-premium">Premium</span> {#trusted-role}

“**信任角色**”让您最可靠的成员能够在紧急情况下立即采取行动：拥有该角色的成员在举报时，可以勾选“**预防性措施**”选项，对被举报用户施加 **24 小时的预防性超时**，等待管理员处理该举报。

1. 使用 [`/settings` 命令](../setup.md#settings)。
2. 打开“**管理**”选项卡。
3. 点击“**举报**”旁边的“**配置**”。
4. 点击“**信任角色**”旁边的“**编辑**”。
5. 在窗口中选择角色，或勾选“**为我创建角色**”（RaidProtect 会创建 `信任举报者` 角色）。将输入框留空则停用信任角色。

预防性超时的运作方式：

- 预防性超时是**静默**的：在管理员确认处罚之前，被举报的用户不会收到私信。
- 其原因为“**预防性处罚：**”加上举报的原因。
- 如果举报针对的是消息，该消息会被删除。
- 警报会被标记为紧急：提及之前会加上“**🛑 紧急举报**”。
- 该处罚与举报绑定：处理该举报的管理员可以确认或撤销它。

:::info
此功能仅限 [**Premium**](/zh-CN/premium) 服务器使用。
:::

### 举报者信誉 {#bad-reporters}

“**虚假举报者**”旁边的“**编辑**”按钮会打开“**举报者信誉**”窗口，用于对举报经常被驳回的成员采取行动：

- **阈值**：采取行动前被驳回的举报数量（3、5、6、10 或 15；默认为“**已停用**”）。
- **时间窗口**：计算周期（7、14、30、60 或 90 天；默认 30 天）。
- 达到阈值后的**操作**：
  - “**通知管理人员**” *（默认）*：发送一条警报，附带“**屏蔽其举报**”按钮和一个处罚按钮（例如：“**警告举报者**”）。
  - “**自动屏蔽**”：该成员无法再提交举报。
  - “**自动处罚**”：执行所配置的处罚。
  - “**屏蔽并处罚**”：同时执行以上两项。
- **处罚**：对虚假举报者执行的处罚（默认为警告，也可选超时、禁言、踢出或封禁）。

<SettingsModal name="reportBad" />

:::info
未配置[禁言角色](./sanctions.mdx#mute)时，禁言处罚会改为超时。
:::

:::tip
您也可以随时通过 [`/block` 命令](./utilities.mdx#block)手动屏蔽某位成员的举报。
:::

## 处理举报 {#manage}

每个举报都会以警报的形式出现在所配置的频道中，并带有多个操作：

- **🙋 接手：** 点击“**接手**”，告知其他管理员您正在处理这个举报。按钮随后会变为“**已接手**”。

- **✅ 已处理：** 如果举报属实但无需处罚（情况已通过其他方式解决：口头提醒、消息已被作者删除……），请点击“**已处理**”。举报会被标记为已接受，但不会处罚被举报的用户。若要处罚，请改用下方的“**处罚该成员…**”菜单。

- **❌ 驳回：** 如果举报不合理，请点击“**驳回**”。驳回的次数会计入[举报者信誉](#bad-reporters)。

- **⚖️ 处罚：** 举报被接手后可用的“**处罚该成员…**”菜单，可让您直接对被举报用户执行处罚，而无需离开举报频道。

启用[分组](#group)后，针对同一成员的后续举报会被添加到现有警报中（例如“**2 位用户举报了 3 条消息和 1 个用户资料**”），而不是新建警报。

:::note
请确保您的管理员已经过良好的培训，懂得如何使用此功能，并鼓励活跃成员负责任地使用它！
:::

## 常见问题 {#faq}

### 如何举报成员或消息？

成员可以在消息或用户资料上点击右键，选择“应用”，然后选择“举报消息”或“举报用户”。他也可以使用信息面板的按钮，或在任何频道中使用 `/report (member)` 命令：随后在窗口中填写原因。

### 举报会发送到哪里？

它们会发送到您配置的举报频道；若未配置，则发送到您的通用日志频道。该频道应仅供管理员使用，以确保举报得到妥善处理。

### 每个举报会提及哪个角色？

提及您配置的通知角色，或 `@everyone`。未设置时，RaidProtect 会提及 `@here`。

### 如何限制虚假举报？

“虚假举报者”设置针对举报经常被驳回的成员。您需要设定一个阈值和一个计算时间窗口，然后选择一项操作：通知管理员、屏蔽其举报、处罚，或两者兼施。您也可以通过 [`/block` 命令](./utilities.mdx#block)手动屏蔽某位成员。
