`/audit` 命令会分析您 Discord 服务器的配置，找出安全漏洞：权限过于宽松、验证级别不足、[未受保护的管理员角色](/zh-CN/learn/least-privilege)等。随后，它会提供一键修复大多数问题的选项。

使用命令：```/audit```

:::info
该命令仅限拥有 `管理员` 权限的成员使用。报告只有您自己可见（临时回复）。
:::

## ❓ 审计的工作原理 {#working}

RaidProtect 会为您的服务器给出一个 **100 分制的总体评分**，附带一个等级（从 **S** 到 **E**）和一个评语：**优秀**（90 分及以上）、**良好**（70 分及以上）、**有待改进**（40 分及以上）或**危急**（低于 40 分）。

报告分为三个类别，每个类别都有各自的评分：

- **服务器设置**
- **角色**
- **频道**

点击某个类别的“**详情**”按钮可查看每项检查的结果，再点击“**返回**”回到报告。“**刷新**”按钮会在您修改设置后重新进行分析。

### 执行的检查 {#checks}

| 类别 | 检查项 |
|---|---|
| 服务器设置 | **验证级别** |
| 服务器设置 | **不当内容过滤器** |
| 服务器设置 | **管理操作的双重验证（2FA）** |
| 服务器设置 | **默认通知设置** |
| 服务器设置 | **突袭警报** |
| 服务器设置 | **私信锁定（公开服务器）** * |
| 服务器设置 | **机器人数量** * |
| 角色 | **@everyone 的权限** |
| 角色 | **可自助获取的角色** |
| 角色 | **由邀请授予的角色** |
| 角色 | **管理员角色** |
| 角色 | **管理员机器人** * |
| 频道 | **@everyone 的频道权限** |
| 频道 | **冗余的频道权限** |
| 频道 | **团队角色的发言允许项** * |
| 频道 | **陈旧的 Webhook** * |

标有 `*` 的检查项仅供**参考**：它们会出现在报告中，但不影响评分。**私信锁定（公开服务器）** 只会出现在社区服务器或公开服务器上。

关于这些检查的几点说明：

- **可自助获取的角色**：指成员无需管理员即可获得的角色，并注明其来源：Discord 新成员引导、RaidProtect 的[自动角色](./onboarding.md#autorole)、助力、订阅、集成或关联角色。
- **团队角色的发言允许项**：某个带有管理权限的角色，在部分频道上拥有已在其他地方涵盖的发言允许项（发送消息、语音发言……）。我们会保留它们，因为在 [`/lock`](./channel-lock.md) 期间或 [DISCON](./discon.md) 1 级时，它们能让团队保留发言权。只需确认所列的每个角色确实是团队角色：否则，它会绕过锁定。

如果 RaidProtect 缺少正常运行所需的权限，除评分之外还会显示一条专门的警告。如果某项检查需要的权限缺失（例如管理 Webhook），则会被标记为未评估。

:::info
如果 RaidProtect 看不到服务器中的某些频道，报告会显示“**分析不完整**”提示框：这些频道不会被分析，评分仅基于其余部分。
:::

## 🔧 一键修复漏洞 {#fix}

可以自动修复的检查项会显示“**修复**”按钮：

| 检查项 | 应用的修复 |
|---|---|
| 验证级别 | 将服务器的验证级别设为**中**（“中”或更高视为通过，“低”给出警告，“无”判为未通过） |
| 不当内容过滤器 | 对**所有成员**启用该过滤器 |
| 默认通知设置 | 将默认通知设置为**仅限 @提及** |
| @everyone 的权限 | 移除 @everyone 角色的敏感权限 |
| 冗余的频道权限 | 打开待清理的频道列表，然后点击“**全部修复**” |

对于**管理员角色**，没有自动修复：审计会建议您使用“**接入**”或“**全部接入**”按钮来保护它们，这会将它们加入 [Authentification Manager](./authentication-manager.mdx)。

:::warning
要应用修复，RaidProtect 必须拥有 `管理服务器` 和 `管理角色` 权限。
:::

### 冗余的频道权限 {#redundant}

当某项频道权限不起任何作用时，它就是**冗余**的：它已在服务器级别授予、已由频道的 @everyone 权限授予，或者是一个没有实际效果的拒绝设置。此时需要在多处修改才能真正起效，这会造成盲区。

列表会逐个频道详细列出每项权限及其冗余的原因：

- 频道的“**忽略**”按钮会将其从列表、评分和“**全部修复**”中移除。您可以在“**已忽略的项目**”中将其恢复。
- 修复某个分类时，也会修复与其同步的频道。
- **管理员**角色的权限会单独列在“**对管理员角色无效**”中：Discord 会忽略它们，我们也从不移除它们，因为一旦该角色失去管理员权限，它们就会生效。

分析会考虑当前正在进行的锁定，无论是通过 [`/lock`](./channel-lock.md) 还是 [DISCON](./discon.md)。

## ✅ 排除有意为之的警示 {#ignore}

有些警示对应的是您有意为之的选择：一个受信任的管理员角色、一个有意保留给 `@everyone` 的权限，等等。在类别详情中提供的“**标记为正常**”按钮，可以让您选择一个项目并将其“**忽略**”。

被忽略的警示会从报告中消失，不再影响您的评分。您可以随时查看已忽略项目的列表（“**已忽略的项目**”按钮），并通过“**恢复**”或“**全部恢复**”还原其中任意一项。

## 常见问题 {#faq}

### 为什么验证级别“中”就足够了？

“中”级别已经会拦截注册不足 5 分钟的账号，从而阻止大多数一次性账号。因此，“**修复**”按钮采用的就是这个级别。

### 为什么审计不会移除我管理员角色的频道权限？

Discord 会忽略拥有管理员权限的角色的频道权限。我们将它们单独列出而不移除：一旦该角色失去管理员权限，它们就会重新生效。

### 我可以将某个频道排除在冗余权限分析之外吗？

可以：在冗余权限列表中点击该频道旁边的“**忽略**”。它将不再计入评分，您也可以在已忽略的项目中将其恢复。
