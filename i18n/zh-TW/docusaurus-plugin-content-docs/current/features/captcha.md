RaidProtect 的**驗證碼**要求每位新成員在進入您的 Discord 伺服器前輸入一組驗證碼，藉由過濾非人類的帳號，阻擋 [selfbot](/zh-TW/learn/self-bot) 與[突襲](/zh-TW/learn/discord-raid)。

這是 RaidProtect 最受歡迎的功能之一，且完全是選用的。您可以選擇何時強制執行：每次加入時、僅在突襲期間，或也對可疑帳號執行。

## ❓ 驗證碼的運作方式 {#working}

驗證碼依賴一個 **@未驗證** 角色和一個 **#驗證** 頻道。當使用者加入您的伺服器時：
- **進入等待**：我們會授予他 **@未驗證** 角色，將他的存取範圍限制在 **#驗證** 頻道。
- **挑戰**：在面板模式下，他在 [RaidProtect Activity](#activity) 中解開一個謎題。在挑戰模式下，他輸入圖片上顯示的驗證碼。請見[顯示模式](#display-mode)。
- **通過**：角色 **@未驗證** 會被移除，成員得以進入伺服器。他的[自動身分組](./onboarding.md#autorole)與[歡迎訊息](./onboarding.md#welcome-message)會在此時發出。
- **失敗**：當他用盡嘗試次數時，會依您的設定被踢出、監禁，或被封鎖幾分鐘後才能再試。被踢出後，他可以回來重新嘗試驗證碼。
- **紀錄**：每次加入都會連同帳號的建立日期記錄在紀錄頻道中，通過、失敗和逾時的情況也一併記錄。
- **診斷**：RaidProtect 會自行找出權限問題、頻道在 Discord [新成員引導](../guides/onboarding.md)中的可見性問題，以及 **@未驗證** 角色的漏洞，並提議修正。

:::info
**預設不踢出**。全新的驗證碼不再踢出未解開驗證碼的成員：他們會留在伺服器上，沒有任何存取權，直到通過驗證。您可以設定[踢出前的延遲](#timeout)。
:::
:::warning
**權限管理**：RaidProtect 會自動設定 **@未驗證** 角色的權限。您可以重新命名該角色與頻道，但請不要刪除。RaidProtect 需要 `KICK_MEMBERS` 和 `MANAGE_ROLES` 權限，且必須位於 **@未驗證** 角色之上。
:::

### 顯示模式 {#display-mode}

| 模式 | 新成員看到的內容 |
|---|---|
| **面板（互動）**，預設 | 一則常駐的「**驗證系統**」訊息，附有「**驗證**」按鈕，可開啟 [RaidProtect Activity](#activity)。成員無法在 **#驗證** 中發言。 |
| **挑戰（經典）** | 成員加入時，會在 **#驗證** 中貼出一張圖片，他在頻道中以訊息輸入驗證碼。 |

面板附有「**Translate**」按鈕，可用成員自己的語言閱讀；每位新加入者都會在驗證頻道中被提及，隨後該訊息會被刪除：他便能藉此找到該頻道。

面板模式能保持頻道整潔，並提供額外的設定：用盡嘗試次數時的處罰選擇、[突襲期間凍結驗證碼](./raid-mode.md#action)、[在入口攔下過新的帳號](./onboarding.md#minage)。挑戰模式則一律會在時限結束或嘗試次數用盡時將成員踢出。

### 觸發方式 {#trigger}

| 觸發方式 | 驗證碼何時適用 |
|---|---|
| **始終**，預設 | 每次加入，無條件。 |
| **自動** | 僅在突襲期間或高 DISCON 等級時。其他新加入者直接進入。 |
| **智慧** | 與自動相同，另加看起來可疑的帳號。 |

使用**自動**時，只有當 [Auto RaidMode](./raid-mode.md#action) 設為「**傳送驗證碼**」或「**突襲期間凍結驗證碼**」時，驗證碼才會在突襲期間強制執行；此外，從等級 3 起的 [DISCON](./discon.md) 警報期間也會強制執行。

**智慧**觸發方式會評估每位新加入者的個人檔案。由您的團隊手動核准的成員，絕不會被視為可疑。

## 🚪 如何設定驗證碼？ {#config}

設定驗證碼既簡單又快速。

1. 使用 [`/settings` 指令](../setup.md#settings)。
2. 開啟「**新成員加入**」分頁。
3. 點擊「**驗證碼**」旁的「**設定**」。
4. 選擇進行驗證碼的頻道，或使用「**幫我建立一個**」按鈕。
5. 點擊「**啟用**」。**@未驗證** 角色會被建立，並在所有頻道中設定其權限。

驗證碼預設以**面板（互動）**模式啟動，觸發方式為**始終**，有 3 次嘗試機會，且沒有踢出前的延遲。之後您可以在同一個畫面中調整每項設定。

### 顯示模式與觸發方式 {#mode}

1. 使用 [`/settings` 指令](../setup.md#settings)。
2. 開啟「**新成員加入**」分頁。

### 在 Activity 中驗證 {#activity}

在**面板**模式下，「**驗證**」按鈕會開啟 **RaidProtect Activity**：成員直接在 Discord 中解開一個小謎題，畫面採用您伺服器的色調，並附有您[新成員引導](../guides/onboarding.md)中的頻道連結。在擁有圖示的 [Premium](/zh-TW/premium) 伺服器上，會顯示伺服器圖示，而非 RaidProtect 標誌。驗證完成後，他會在其中看到自己的[歡迎卡片](./onboarding.md#welcome-message)。

- **謎題失敗**：與輸入錯誤驗證碼相同，會消耗一次嘗試機會，並在嘗試次數用盡時施加預定的處罰。Activity 會先向成員告知結果，然後才施加處罰。
- **通過**：成員離開成功畫面時即完成驗證。如果他在這段期間點擊「**驗證**」，他的驗證會立即生效，而不是重新開啟 Activity。
- **機器人**：由自動程式解開的驗證碼會被立即處罰，如同用盡嘗試次數一樣：依您的設定為踢出、監禁或封鎖。
- **由您的團隊審核**：有疑慮時，該成員會被擋在入口，且不會開始倒數任何時限，同時您的團隊會收到驗證碼的自動報告。報告會送到[驗證碼紀錄](#logs)；若無，則送到[檢舉](./reports.md)頻道；若再無，則送到伺服器紀錄。報告被受理後，會提供「**放行**」、「**連結到其他成員**」（搭配 [Identity Update](#activity-alts)）與「**拒絕**」；「**拒絕**」會施加您設定的驗證碼失敗處理方式（踢出、監禁或封鎖）：此處不提供處罰選單。
- **嘗試次數用盡後的監禁**：此監禁沒有期限，同時會開啟一份審核報告。「**放行**」會解除監禁並讓成員通過驗證；否則請處罰他。
- **裝置驗證遭拒**：Activity 會在[驗證成員的裝置](#privacy)前先徵求同意。如果他拒絕，會如同用盡嘗試次數一樣受到失敗處理方式（踢出、監禁或封鎖）。
- **Activity 無法開啟**：成員可以點擊「**輸入驗證碼**」。正確的驗證碼之後會交由您的團隊審核。
- **資料刪除**：成員可以寄信至 [privacy@raidprotect.bot](mailto:privacy@raidprotect.bot) 要求刪除其驗證資料。此後他需要重新通過驗證碼，而他的處罰會保留。

#### 由驗證碼發現的多帳號 <span className="badge-experiment">實驗</span> {#activity-alts}

搭配 [Identity Update](./alt-accounts.md)，Activity 也會找出可能與您伺服器某位成員為同一人所有的新加入者：

- **確定的關聯**：帳號會在 [`/alt`](./alt-accounts.md#alt) 中自動關聯。驗證碼紀錄會提示此事，並附有「**取消連結**」按鈕。如果該群組正在受到處罰，或[每人僅限一個帳號](./alt-accounts.md#single-account)限制了其次要帳號，新加入者會受到群組的處罰或被隔離。
- **可能的關聯**：如果已啟用[每人僅限一個帳號](./alt-accounts.md#single-account)，該成員會進入審核。「**連結到其他成員**」會在 `/alt` 中關聯這些帳號並放行他；如果沒有偵測到任何帳號，會跳出視窗請您選擇成員（「**已在伺服器中的帳號**」）。否則，該成員會直接進入，驗證碼紀錄會提示這個可能的關聯，並附有「**連結**」按鈕。
- **未套用的確定關聯**：如果群組中有帳號屬於伺服器團隊、新加入者與多個 `/alt` 群組有關聯，或兩個帳號各自已有群組（兩個群組絕不會自動合併），則不會自動關聯任何帳號。此時會以相同方式向您建議這個關聯。

只會向您顯示您伺服器中的帳號：不會透露任何其他伺服器的資訊。

:::info 實驗：Identity Update
多帳號的偵測屬於預計於 3.7.0 版推出的 **Identity Update**。在正式推出之前，它處於實驗階段，為 [Premium](/zh-TW/premium) 伺服器提供公開測試版。
:::

### 隱私：不取得 IP 位址 {#privacy}

RaidProtect 不會取得通過驗證碼的成員的 IP 位址，Activity 本身也會向成員顯示這一點。

- **在 Discord 中，不經外部網站**：Activity 在 Discord 中開啟，其通訊經由 Discord 的代理伺服器，而代理伺服器不會將成員的 IP 位址傳給我們。我們從來看不到它，因此既無法保存，也無法比對。機器人本身也收不到：Discord 不會將 IP 位址提供給任何機器人。
- **經成員同意的裝置驗證**：在謎題開始前，Activity 會徵求成員同意驗證其裝置，以找出自動程式與多帳號。我們記錄的內容用來辨認曾經見過的裝置，而不是用來得知使用者是誰。
- **您的團隊只會看到結果**：通過、失敗、審核或多帳號關聯，絕不會看到裝置的特徵。
- **挑戰模式**：成員在頻道中以訊息輸入驗證碼，不會記錄其裝置的任何資訊。

成員可以寄信至 [privacy@raidprotect.bot](mailto:privacy@raidprotect.bot) 要求刪除其驗證資料。若想了解驗證成員的各種方式，請閱讀我們關於[Discord 上的驗證碼與驗證](/zh-TW/learn/captcha-discord)的文章。

### 測試驗證碼 {#test-mode}

不需要啟用任何設定：在面板模式下，已通過驗證的團隊成員（擁有者，或擁有**管理員**或**管理伺服器**權限的成員）隨時都可以點擊「**驗證**」，重複進行驗證碼。嘗試次數與解答時間的規則與新加入的成員相同。不會套用任何處置：驗證碼紀錄（「**團隊測試**」）會說明原本會執行的處置。

3. 點擊「**驗證碼**」旁的「**設定**」。
4. 點擊「**難度**」旁的「**編輯**」。
5. 調整視窗中的欄位，然後確認。

:::

### 踢出前的延遲 {#timeout}

在面板模式下，此延遲從成員加入時開始計算：如果他沒有及時通過驗證，就會受到您的失敗處理方式（踢出、監禁或封鎖）。

1. 使用 [`/settings` 指令](../setup.md#settings)。
2. 開啟「**新成員加入**」分頁。
3. 點擊「**驗證碼**」旁的「**設定**」。
4. 在「**踢出前的延遲**」中，選擇「**停用**」、5、15 或 30 分鐘，或選擇 30 秒至 30 分鐘的「**自訂值**」。

:::warning
若停用延遲，未驗證的帳號會留在伺服器上，並可以私訊您的成員。請設定延遲，或使用[私訊鎖定](./dm-lock.mdx)關閉私訊。
:::

### 驗證碼畫面的警示 {#alerts}

當有狀況妨礙驗證正常運作時，驗證碼畫面會顯示提示區塊：
- **加入時頻道不可見**：驗證頻道不在 Discord 新成員引導的任何預設頻道中。請點擊「**移至** _分類_」或「**建立新分類**」讓我們為您修正，或參考[新成員引導指南](../guides/onboarding.md)。
- **@未驗證 角色的漏洞**：新成員引導在給予 **@未驗證** 的同時給予了其他角色而繞過驗證、**@未驗證** 角色帶有權限、**@everyone** 擁有 `ADMINISTRATOR` 權限，或有頻道對驗證中（或監禁中）的成員仍然可見。「**修復**」按鈕會關閉相關頻道。
- **驗證等級為高**：這個 Discord 等級會讓成員等待 10 分鐘才能發言。驗證碼已經過濾了入口：搭配驗證碼建議使用**中等**。
- **缺少權限**：RaidProtect 需要 `KICK_MEMBERS` 和 `MANAGE_ROLES`。

問題解決後，請點擊「**重新整理**」。

### 停用或刪除驗證碼 {#disable}

1. 使用 [`/settings` 指令](../setup.md#settings)。
2. 開啟「**新成員加入**」分頁。
3. 點擊「**驗證碼**」旁的「**設定**」。
4. 在「**顯示模式**」中，選擇：
   - 「**停用**」以暫停驗證，且不會遺失任何設定；
   - 「**刪除**」以清除設定與驗證角色。RaidProtect 會要求您確認。

:::tip
若希望驗證碼在突襲之外保持低調，建議將其[觸發方式](#trigger)設為**自動**，而不是停用它。
:::

## ✨ 額外功能 {#additional-features}

### 獨立紀錄 {#logs}

如果您的伺服器人氣很高，與驗證碼相關的紀錄可能會塞滿您的主要紀錄頻道。您可以將它們移到另一個頻道。

1. 使用 [`/settings` 指令](../setup.md#settings)。
2. 開啟「**新成員加入**」分頁。
3. 點擊「**驗證碼**」旁的「**設定**」。
4. 點擊「**紀錄**」旁的「**編輯**」。
5. 選擇要發送驗證碼紀錄的頻道。

您也可以在「**管理**」分頁 >「**紀錄**」中的「**驗證碼**」那一行找到這項設定。

### 自動身分組 {#autorole}

自動身分組不再於驗證碼中設定：它已併入「**新成員加入**」分頁的[自動身分組](./onboarding.md#autorole)，可接受多個角色。您原有的設定已自動沿用到那裡。驗證碼啟用時，這些角色會在通過驗證碼後授予。

### 繞過驗證碼 {#bypass}

使用指令：```/bypass captcha [user]```

將 `[user]` 替換為所需的 [ID](../guides/id.mdx)，該使用者將有 10 分鐘的時間加入伺服器，且不需要解答驗證碼。如果該使用者已在伺服器中，驗證碼會被自動視為已解答。您也可以不指定使用者來使用此指令，以查看目前的繞過使用者清單。

## 🤝 驗證碼與防突襲，搭配更強大 {#raid}

驗證碼會與其他新成員防護功能協同運作：
- [**Auto RaidMode**](./raid-mode.md#action)：使用「**傳送驗證碼**」處理方式時，一波人潮中的新加入者會通過驗證碼，而不是被踢出。使用「**突襲期間凍結驗證碼**」時，他們會在驗證碼之後等待，待這波人潮結束後再通過。
- **[帳號最短註冊時長](./onboarding.md#minage)**：「**攔在入口**」處理方式會把過新的帳號卡在驗證碼上，直到帳號達到年齡後才能解答。
- [**DISCON**](./discon.md#captcha)：從等級 4 起，若已設定驗證碼就會啟用，即使您原本已停用也一樣。從等級 3 起，無論其觸發方式為何，都會對所有新加入者強制執行。

## 常見問題 {#faq}

### 有多少時間可以解答驗證碼？

在面板模式下，成員預設有 3 次嘗試機會（1 到 10 次），並預設有 30 秒解開謎題（可停用，最長 5 分鐘），從第一個挑戰起算。預設不套用踢出延遲，但您最多可設定到 30 分鐘。在挑戰模式下，他預設有 5 分鐘（30 秒至 15 分鐘）的時間，之後會被踢出。

### 如果成員驗證碼失敗會怎樣？

當他用盡嘗試次數時，會被踢出伺服器；在面板模式下，若您選擇了監禁或封鎖，則會被監禁，或被封鎖 10 分鐘後才能再試。被踢出後，他可以回來重新嘗試驗證碼。

### 未驗證的成員會被自動踢出嗎？

全新的驗證碼不會：在面板模式下，踢出前的延遲預設為停用。未驗證的成員會留在伺服器上，無法存取任何頻道。請設定踢出前的延遲，或關閉伺服器的私訊，以避免他們私訊您的成員。

### 可以只在突襲期間啟用驗證碼嗎？

可以。將其觸發方式設為**自動**，並將 Auto RaidMode 的處理方式設為「**傳送驗證碼**」或「**突襲期間凍結驗證碼**」。其餘時間，新加入者會直接進入。

### 使用驗證碼需要啟用 Discord 社群嗎？

不需要，驗證碼無需社群即可運作。如果已啟用社群，請確認驗證頻道屬於[新成員引導](../guides/onboarding.md)的預設頻道之一。

### 可以讓某位成員免除驗證碼嗎？

可以，使用 `/bypass captcha [user]` 指令。該成員有 10 分鐘可以不解答驗證碼就加入；如果他已在伺服器中，驗證碼會被自動視為已解答。

### 可以重新命名 @未驗證 角色和 #驗證 頻道嗎？

可以，您可以自由重新命名它們。請不要刪除，因為 RaidProtect 需要它們來讓驗證碼運作，並會自動設定它們的權限。
