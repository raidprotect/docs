RaidProtect 的檢舉系統讓您的社群只需幾下點擊，就能透過右鍵、專屬按鈕或 `/report` 指令，向管理人員回報任何可疑的訊息或成員。它可以進行設定，以最佳化您團隊處理檢舉的方式。

## ❓ 檢舉的運作方式 {#working}
成員可以透過 4 種主要方式檢舉內容。

1. **在訊息上按右鍵**
成員可以在他認為違反規則的訊息上按右鍵，選擇 **`應用程式`**，然後點擊 **`檢舉訊息`**。接著會開啟一個視窗，讓他說明檢舉的原因。

2. **在個人檔案上按右鍵**
同樣地，成員可以在他認為有問題的個人檔案上按右鍵，選擇 **`應用程式`**，然後點擊 **`檢舉使用者`**。接著會開啟一個視窗，讓他說明檢舉的對象（頭像、使用者名稱、自我介紹、語音活動、私訊活動）及原因。

3. **資訊面板上的按鈕**
如果在[資訊面板（`/display public`）](./display.mdx)上啟用了「檢舉」功能，面板下方會直接提供「**檢舉成員**」按鈕，讓成員能快速檢舉某位使用者。

4. **斜線指令**
成員也可以在伺服器的任何頻道中，透過 **`/report`** 指令檢舉使用者。

使用指令：```/report (member)```

將 `(member)` 替換為想要檢舉的使用者。原因隨後在視窗中輸入，與在個人檔案上按右鍵時相同。

:::info
啟用檢舉也會啟用[訊息快取](./moderation.mdx#snipe)：RaidProtect 會在記憶體中保留一小時的訊息，以便將被檢舉的內容附在警報中。
:::

## 🚩 設定檢舉 {#config}

檢舉會送到**檢舉頻道**。如果您沒有選擇頻道，檢舉就會送到您的一般紀錄頻道。所有設定都在同一個畫面中：

1. 使用 [`/settings` 指令](../setup.md#settings)。
2. 開啟「**管理**」分頁。
3. 點擊「**檢舉**」旁的「**設定**」。
4. 點擊畫面標題右側的「**啟用**」，開啟檢舉系統。

<Settings start="reports" />

### 設定頻道 {#config-channel}

1. 使用 [`/settings` 指令](../setup.md#settings)。
2. 開啟「**管理**」分頁。
3. 點擊「**檢舉**」旁的「**設定**」。
4. 點擊「**接收檢舉**」旁的「**編輯**」。
5. 在視窗中，選擇想要的頻道（_例如：#檢舉 或 #reports_），或勾選「**為我建立頻道**」，讓 RaidProtect 建立一個私人的 `檢舉` 頻道。

如果您沒有選擇任何頻道，或選擇了紀錄頻道，檢舉就會跟隨您的一般紀錄頻道。

<SettingsModal name="reportChannel" />

### 設定通知角色 {#config-role}

1. 使用 [`/settings` 指令](../setup.md#settings)。
2. 開啟「**管理**」分頁。
3. 點擊「**檢舉**」旁的「**設定**」。
4. 點擊「**通知角色**」旁的「**編輯**」。
5. 在視窗中，選擇想要的角色（_例如：@管理人員 或 @檢舉通知_），或勾選「**其他提及**」：`@everyone`、`@here` 或「**為我建立角色**」（RaidProtect 會建立 `新檢舉` 角色）。

如果沒有設定角色，則會提及 `@here`。

<SettingsModal name="reportRole" />

:::warning
該頻道必須保留給管理人員和管理員使用，以確保檢舉能被妥善處理。
:::

### 檢舉分組 {#group}

「**分組**」開關決定了針對同一成員的多個檢舉如何呈現：

- **已啟用** *（預設）*：針對同一成員的檢舉會合併為一則警報。
- **已停用**：每個檢舉都會產生各自獨立的警報。

在檢舉畫面中，點擊「**分組**」旁的「**啟用**」或「**停用**」。

<a id="config-notify"></a>

### 檢舉者通知 {#notify}

「**檢舉者通知**」旁的「**編輯**」按鈕會開啟一個視窗，讓您選擇發出檢舉的成員在其檢舉被處理後，會透過私訊收到什麼內容：

| 等級 | 效果 |
|---|---|
| **停用** | 檢舉者不會收到任何通知。 |
| **僅告知已處理** *（預設）* | 告知檢舉者其檢舉已被處理。 |
| **附帶處理結果** | 告知檢舉被受理還是被駁回。 |
| **附帶管理人員** | 同時告知該檢舉由哪位管理人員處理。 |

即使檢舉已與其他檢舉合併，檢舉者每個檢舉也只會收到一則訊息。

### 信任角色 <span className="badge-premium">Premium</span> {#trusted-role}

「**信任角色**」讓您最可靠的成員能在緊急情況下立即採取行動：當擁有此角色的成員提出檢舉時，可以勾選「**預防性措施**」選項，對被檢舉的使用者施加**為期 24 小時的預防性超時**，等待管理人員處理該檢舉。

1. 使用 [`/settings` 指令](../setup.md#settings)。
2. 開啟「**管理**」分頁。
3. 點擊「**檢舉**」旁的「**設定**」。
4. 點擊「**信任角色**」旁的「**編輯**」。
5. 在視窗中，選擇角色，或勾選「**為我建立角色**」（RaidProtect 會建立 `信任檢舉者` 角色）。將欄位留空即可停用信任角色。

預防性超時的運作方式：

- 預防性超時是**靜默**的：在管理人員確認處罰之前，被檢舉的使用者不會收到私訊。
- 其原因為「**預防性處罰：**」後面接檢舉的原因。
- 如果檢舉針對的是訊息，該訊息會被刪除。
- 警報會被標示為緊急：提及前會加上「**🛑 緊急檢舉**」。
- 處罰與檢舉相關聯：處理該檢舉的管理人員可以確認或取消它。

:::info
此功能僅限 [**Premium**](/zh-TW/premium) 伺服器使用。
:::

### 檢舉者信譽 {#bad-reporters}

「**虛假檢舉者**」旁的「**編輯**」按鈕會開啟「**檢舉者信譽**」視窗，讓您對檢舉經常被駁回的成員採取措施：

- **閾值**：採取措施前被駁回的檢舉數量（3、5、6、10 或 15；預設為「**停用**」）。
- **時間範圍**：計算的期間（7、14、30、60 或 90 天；預設 30 天）。
- 達到閾值後的**處理方式**：
  - 「**通知管理人員**」*（預設）*：發送警報，並附上「**封鎖其檢舉**」按鈕和處罰按鈕（例如：「**警告該檢舉者**」）。
  - 「**自動封鎖**」：該成員無法再提出檢舉。
  - 「**自動處罰**」：套用所設定的處罰。
  - 「**封鎖並處罰**」：結合上述兩種處理方式。
- **處罰**：套用於虛假檢舉者的處罰（預設為警告，或超時、禁言、踢出或停權）。

<SettingsModal name="reportBad" />

:::info
如果沒有設定[禁言角色](./sanctions.mdx#mute)，禁言處罰會改為超時。
:::

:::tip
您也可以隨時使用 [`/block` 指令](./utilities.mdx#block)手動封鎖某位成員的檢舉權限。
:::

## 管理檢舉 {#manage}

每個檢舉都會以警報的形式送到所設定的頻道，並附有多個動作：

- **🙋 接手**：點擊「**接手**」，告知其他管理人員您正在處理這個檢舉。按鈕隨後會變成「**已接手**」。

- **✅ 已處理**：如果檢舉屬實，但不需要處罰（已用其他方式解決：口頭提醒、訊息已由作者刪除……），請點擊「**已處理**」。該檢舉會被標示為受理，但不會處罰被檢舉的使用者。若要處罰，請改用下方的「**處罰該成員…**」選單。

- **❌ 駁回**：如果檢舉並不合理，請點擊「**駁回**」。駁回會計入[檢舉者信譽](#bad-reporters)。

- **⚖️ 處罰**：「**處罰該成員…**」選單在檢舉被接手後即可使用，讓您無需離開檢舉頻道，就能直接對被檢舉的使用者施加處罰。

當[分組](#group)啟用時，針對同一成員的後續檢舉會加入現有的警報中（例如「**3 則訊息與 1 份個人資料被 2 位使用者檢舉**」），而不是建立新的警報。

:::note
請確保您的管理人員已受過此功能的使用訓練，並鼓勵您活躍的成員負責任地使用它！
:::

## 常見問題 {#faq}

### 如何檢舉成員或訊息？

成員可以在訊息或個人檔案上按右鍵，選擇「應用程式」，然後選擇「檢舉訊息」或「檢舉使用者」。也可以透過資訊面板的按鈕，或在任何頻道中使用 `/report (member)` 指令：原因隨後在視窗中輸入。

### 檢舉會送到哪裡？

會送到您所設定的檢舉頻道，若未設定則送到您的一般紀錄頻道。該頻道必須保留給管理人員和管理員使用，以確保檢舉能被妥善處理。

### 每次檢舉時會提及哪個角色？

您所設定的通知角色，或 `@everyone`。若未設定，RaidProtect 會提及 `@here`。

### 如何限制虛假檢舉？

「虛假檢舉者」設定針對檢舉經常被駁回的成員。您設定一個閾值和計算的時間範圍，然後選擇處理方式：通知管理人員、封鎖其檢舉、處罰，或兩者並行。您也可以使用 [`/block` 指令](./utilities.mdx#block)手動封鎖某位成員。
