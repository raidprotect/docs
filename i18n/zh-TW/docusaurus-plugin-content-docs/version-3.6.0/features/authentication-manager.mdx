RaidProtect 的 **Authentification Manager**（AM）透過真正的身份驗證，保護對您最敏感的 Discord 角色的存取。藉由 passkey（WebAuthn）、PIN 碼與 OTP，成員必須先通過驗證，才能取得[敏感角色](/zh-TW/learn/least-privilege)，且僅限一段有限的時間。在 Discord 中，該模組顯示的名稱為「**Authentification Manager**」。

## ❓ Authentification Manager 的運作方式 {#working}

Authentification Manager 建立在**受保護的角色**與**臨時會話**之上。當管理員以 AM 保護某個角色時：

1. 該 Discord 角色不再是永久授予的：必須通過驗證才能取得。
2. 獲授權的成員使用 `/auth` 指令（或[工作人員面板](./display.mdx#staff)上的「**獲取角色**」按鈕）進行驗證。
3. 系統會依該角色所定義的時長建立**臨時會話**。
4. 會話到期時，我們會自動移除該角色。

:::info
每位成員必須先使用 `/auth-profile` 建立自己的**驗證設定檔**，才能進行驗證。
:::

在會話期間，成員的 Discord 動作（停權、刪除訊息、釘選、修改頻道……）會連同其對象一併記錄在 AM 的日誌中：您可以知道每個受保護的角色做了什麼。

## 🔐 安全等級 {#grades}

每種驗證方式都對應一個**安全等級**。每個受保護的角色都要求成員達到一個最低等級。

| **等級**                                                                    | **條件**                              |
| --------------------------------------------------------------------------- | ------------------------------------- |
| <Icon src="/img/icons/RankS.svg" alt="icon RankS" title=":securityRankS:"/> | 至少註冊一個 passkey                  |
| <Icon src="/img/icons/RankA.svg" alt="icon RankA" title=":securityRankA:"/> | 已啟用 OTP 碼（2FA）                  |
| <Icon src="/img/icons/RankB.svg" alt="icon RankB" title=":securityRankB:"/> | 8 位數以上的強化 PIN                  |
| <Icon src="/img/icons/RankC.svg" alt="icon RankC" title=":securityRankC:"/> | 6 位數以上的強化 PIN                  |
| <Icon src="/img/icons/RankD.svg" alt="icon RankD" title=":securityRankD:"/> | 6 位數以上的簡易 PIN                  |
| <Icon src="/img/icons/RankE.svg" alt="icon RankE" title=":securityRankE:"/> | 4 位數以上的簡易 PIN                  |

:::tip
系統會自動採用您已設定的各種方式中最高的等級。例如，如果您有簡易 PIN（D 級）和 passkey（S 級），您的等級就是 **S**。
:::

## 🛡️ 驗證方式 {#methods}

<SeparatedBox>
<Tabs>
<TabItem value="pin" label="PIN" default>

PIN 碼是最簡單的方式。提供兩種模式：

- **簡易 PIN**：在視窗中以一般方式輸入（4 到 12 位數）。
- **強化 PIN**：數字鍵盤，其按鍵位置在每次輸入時都會改變（6 到 12 位數），以防止他人看著您輸入而猜出您的密碼。

:::warning
過於簡單的 PIN 會被拒絕：重複的數字、遞增或遞減的序列，以及常見的模式。
:::

</TabItem>
<TabItem value="otp" label="OTP（2FA 碼）">

OTP 採用 TOTP（Time-based One-Time Password）標準，相容於驗證器應用程式，例如 [Google Authenticator](https://play.google.com/store/apps/details?id=com.google.android.apps.authenticator2)、[Authy](https://authy.com/)、[1Password](https://1password.com/)、[Dashlane](https://www.dashlane.com/) 或 [Bitwarden](https://bitwarden.com/)。

- 6 位數的驗證碼，每 30 秒更新一次。

</TabItem>
<TabItem value="passkey" label="Passkey（WebAuthn）">

Passkey 提供最高的安全等級（S 級）。驗證在瀏覽器中進行，可使用：

- **指紋**或**臉部辨識**（Touch ID、Face ID、Windows Hello）。
- **實體安全金鑰**（YubiKey 等）。

使用 passkey 時，會在您的瀏覽器中開啟外部連結，語言與您的 Discord 相同。驗證通過後，系統便會授予您該角色。

</TabItem>
</Tabs>
</SeparatedBox>

## 👤 驗證設定檔（`/auth-profile`） {#auth-profile}

`/auth-profile` 指令用來管理您個人的驗證設定檔。它可在任何伺服器以及私訊中使用，且您的設定檔在各處都相同。

<Settings start="authProfile" />

### 首次使用 {#onboarding}

首次使用時，會出現歡迎畫面，介紹等級、臨時會話與驗證方式。點擊「**繼續**」來設定您的第一個驗證方式。

### 管理驗證方式 {#manage-methods}

在您的設定檔中，您可以：

- 新增、變更或刪除 **PIN 碼**（簡易或強化）。
- 透過 QR code 或密鑰啟用 **2FA 碼**（OTP），重新產生或刪除它。
- 從註冊頁面新增 **passkey**，或刪除其中一個。每個 passkey 都會顯示裝置名稱及上次使用日期。
- **重新命名** passkey：「**新增**」旁的「**編輯 Passkey**」按鈕會開啟一個視窗，列出您的 passkey 並讓您輸入新名稱（例如 `MacBook`、`iPhone`、`YubiKey`）。重新命名會記錄在您的稽核日誌中。

如果您已經有驗證方式，我們會在您新增或修改之前要求您先通過驗證。設定檔底部會提示您目前的等級，以及要再提升一級所需新增的驗證方式。

:::info
刪除某個驗證方式可能會降低您的等級。此時，您對要求更高等級的角色的存取權會被停用。
:::

### 進行中的會話 {#profile-sessions}

您進行中的會話及其到期時間，會顯示在各伺服器上 [`/auth`](#sessions) 指令的面板中。

### 稽核日誌 {#profile-audit}

您的設定檔會顯示您帳號上最近 3 次的動作。「**檢視完整紀錄**」按鈕會開啟分頁的完整日誌，並附上相關的伺服器。

### 重設帳號 {#reset}

「**我忘記了驗證方式**」按鈕會完全重設您的帳號。此動作會：

- 刪除您所有的驗證方式（PIN、2FA、passkey）；
- 停用您在所有伺服器上對受保護角色的存取權；
- 要求您重新設定所有項目。

:::danger
此動作無法復原。您所有的存取權會立即被撤銷。
:::

## 🔑 進行驗證（`/auth`） {#auth}

`/auth` 指令用來進行驗證以取得受保護的角色。

使用指令：```/auth [role]```

### 驗證流程 {#auth-flow}

1. 在伺服器上執行 `/auth` 指令，或點擊工作人員面板中的「**獲取角色**」。
2. 選單會顯示可用的角色及其所需等級與會話時長。
3. 選擇一個或多個角色（最多 10 個）。只需以其中要求最高的等級驗證一次，即可全部開啟。
4. 從達到該角色等級的驗證方式中選擇一種。
5. 進行驗證（PIN、OTP 或 passkey）。
6. 成功後，我們會授予您該（或這些）Discord 角色，並為每個角色建立一個會話。這些會話會記錄在 Authentification Manager 的紀錄中。

:::info
選單中只會顯示您被指派且狀態為**有效**的角色。
:::

### 管理會話 {#sessions}

`/auth` 面板會列出您進行中的會話。對每個會話，您都可以：

- **延長會話**：重新驗證，以重新取得完整的時長。
- **結束會話**：會話會立即被撤銷，且 Discord 角色會被移除。

### 安全性 {#auth-security}

- **警告**：失敗 3 次嘗試後會出現警告訊息。
- **鎖定**：失敗 5 次後，您的帳號會被鎖定 1 小時。
- **重設**：失敗 10 次後，您的帳號會被重設，且您所有的存取權都會被撤銷。

## ⚙️ 伺服器設定 {#auth-settings}

Authentification Manager 的設定面板有兩種開啟方式：

1. 使用 [`/settings` 指令](../setup.md#settings)。
2. 開啟「**防護**」分頁。
3. 點擊「**Authentification Manager**」旁的「**設定**」。

面板會取代儀表板，並附有「**返回**」按鈕以回到防護分頁。您也可以直接使用 `/auth-settings` 指令，它會開啟相同的面板。

<Settings start="auth" />

:::info
`/auth-settings` 指令預設僅限管理員使用。若要讓非管理員的管理者使用它，請在**伺服器設定 > 整合 > RaidProtect** 中為他授權。
:::

### 權限 {#permissions}

| **角色**        | **存取權限**                                                              |
| --------------- | ------------------------------------------------------------------------- |
| 擁有者          | 完整存取                                                                  |
| 管理員          | 完整存取（除非管理員權限來自受 AM 保護的角色）                            |
| 管理者          | 有限存取：必須通過驗證，只能管理位階在他之下的角色與使用者，不能修改伺服器設定 |

#### 管理者驗證 {#manager-auth}

既非擁有者也非管理員的管理者，每次開啟面板時都必須通過驗證。我們會提供達到**管理者最低等級**的驗證方式：「**使用 PIN 驗證身份**」、「**使用 OTP 驗證身份**」或「**使用 Passkey 驗證身份**」。強化 PIN 須在按鍵位置會變動的鍵盤上輸入。

與 `/auth` 相同的保護機制同樣適用：失敗 3 次後警告、失敗 5 次後鎖定一小時、失敗 10 次後重設帳號。

### 伺服器參數 {#server-settings}

點擊「**伺服器設定**」旁的「**編輯**」，即可開啟「**伺服器身份驗證設定**」視窗：

- **預設會話時長**：新角色所採用的時長，格式如 `30m`、`2h` 或 `1d`。免費版最長 8 小時，[Premium](/zh-TW/premium) 版最長 24 小時。預設：10 分鐘。
- **預設最低等級**：新角色所採用的等級。預設：A。
- **管理者最低等級**：管理者開啟面板所必須達到的等級。預設：A。
- **Webhook URL（留空以清除）**：接收 AM 紀錄的 Discord Webhook（選填）。僅接受 Discord Webhook 的 URL。

管理者無法修改這些參數。

### 角色分頁 {#roles-tab}

角色分頁會列出您受保護的角色，以及其等級、會話時長與使用者數量。在分頁下方，「**最近的會話**」區塊會顯示最新的會話，「**檢視全部**」則會開啟所有會話的清單。

:::info
**限制**：免費版 3 個角色，[Premium](/zh-TW/premium) 版 10 個角色。已停用的角色仍會佔用一個欄位。
:::

#### 新增角色 {#add-role}

1. 開啟 Authentification Manager 面板（見[上方](#auth-settings)）。
2. 在「**角色**」分頁中，點擊「**新增**」。
3. 選擇要保護的 **Discord 角色**。
4. 選擇**最低安全等級**。
5. 填入**會話時長**。
6. 選擇**整合策略**（見下文）。
7. 我們會偵測已擁有該角色的成員：調整選擇後，點擊「**發送邀請**」（或「**忽略**」）。

每位被選取的成員都會與該角色建立關聯：若其等級足夠，狀態為**有效**，否則為**已邀請**：他會收到一則私訊，邀請他設定 `/auth-profile`。

<SettingsModal name="authAddRole" />

我們會拒絕由整合所管理的角色、用於 Discord 新成員引導的角色、位階高於 RaidProtect 角色或高於您自己角色的角色，以及已受保護的角色。

##### 整合策略 {#strategies}

| **策略** | **效果** |
|---|---|
| 「**直接使用此角色**」 | 所選角色會直接成為受保護的角色。這是預設選項。 |
| 「**建立獨立的權限角色**」 | 我們會在所選角色的正下方建立一個帶有原始權限的 `🔑 <角色名稱>` 角色，並清空原角色的權限。原角色會永久保留其顏色與顯示外觀，受保護的是新角色。 |

:::tip
如果您的角色在成員清單中是**獨立顯示**的，請選擇「**建立獨立的權限角色**」：您的成員會永久保有可見的角色，而敏感權限只會在通過驗證的會話期間授予。

使用獨立角色時，顯示角色的頻道管理權限也會轉移到 `🔑` 角色。對於管理員角色，「**在會話以外保留所有頻道的檢視權限**」選項可讓顯示角色在會話以外仍能檢視所有頻道；若未啟用，它在沒有管理員權限時將看不到任何頻道。
:::

#### 從 `/audit` 保護管理員角色 {#audit-bulk}

[稽核](./audit.md)中的管理員角色檢查提供了「**全部整合**」：您可以一次保護尚未受保護的管理員角色，每批最多 5 個角色，並受限於您的空位數量。只會提供位階低於 RaidProtect 與您最高角色的角色。

#### 編輯角色 {#edit-role}

點擊角色那一行的「**編輯**」以開啟其資料卡（最低等級、會話時長、已指派的使用者），再點擊「**編輯**」來變更最低等級與會話時長。

#### 啟用／停用角色 {#toggle-role}

在角色的資料卡中，「**停用**」會暫停該角色而不刪除它：不再為其建立任何會話。進行中的會話會被撤銷，並從相關成員身上移除 Discord 角色。「**啟用**」會讓它恢復運作，但受限於您的欄位數量。

#### 刪除角色 {#delete-role}

「**刪除**」會將該角色及所有使用者指派從 Authentification Manager 中永久移除。系統會要求您確認。

### 使用者分頁 {#users-tab}

使用者分頁會列出與至少一個受保護角色相關聯的成員，以及其等級、角色數量與管理者狀態。

:::info
**限制**：免費版 20 位使用者，[Premium](/zh-TW/premium) 版 50 位。
:::

#### 新增使用者 {#add-user}

1. 開啟「**使用者**」分頁。
2. 點擊「**新增**」。
3. 選擇要指派給他的**使用者**與**身份驗證角色**。

成員會收到一則私訊：若其等級足夠，就可以立即使用該角色，否則會被邀請設定等級足夠的驗證方式。

:::info
邀請數量受到限制，以避免垃圾訊息。被擋下的邀請可稍後從成員的資料卡重新發送。
:::

#### 使用者資料卡與狀態 {#member-status}

點擊「**管理**」以開啟成員的資料卡：他的等級、ID、是否為管理者，以及他的每個角色及其狀態。角色選單可用來新增或移除角色。

| **狀態**    | **說明**                                                          |
| ----------- | ----------------------------------------------------------------- |
| 已邀請      | 成員已被新增，但其等級尚不足（需設定設定檔）                      |
| 等待中      | 等待批准：點擊「**批准**」                                        |
| 有效        | 成員可以進行驗證以取得該角色                                      |
| 已停用      | 存取已暫停：點擊「**恢復**」以重新啟用                            |

#### 設為管理者 {#promote-manager}

「**設為管理者**」讓成員可以存取設定面板，前提是他達到管理者最低等級。管理者管理位階在他之下的使用者與角色。「**移除管理者**」會移除他的此項存取權。

#### 刪除使用者 {#delete-user}

「**刪除使用者**」會將成員從伺服器上所有受保護的角色中移除。系統會要求您確認。

### 紀錄分頁 {#logs-tab}

紀錄分頁會以分頁方式顯示 Authentification Manager 的日誌：已授予、延長或撤銷的會話、設定變更……。眼睛形狀的按鈕可開啟某筆記錄的詳細資訊（使用者、動作、類型、日期、角色與對象）。紀錄也會發送到所設定的 Webhook。

### 會話 {#sessions-tab}

沒有專屬的分頁：角色分頁的「**最近的會話**」區塊會顯示最新的會話，「**檢視全部**」則會開啟伺服器所有會話的清單及其狀態（有效、已過期、已撤銷）。「**檢視**」會顯示某個會話的詳細資訊及其最近的動作。

### 新成員引導保護 {#onboarding-protection}

如果受保護的角色被加到 Discord 新成員引導的問題中，我們會自動將它從問題中移除並記錄在日誌中：否則，任何新加入者都可以不經驗證就取得該角色。

### Premium 結束時 {#premium-end}

[Premium](/zh-TW/premium) 訂閱結束時，超過 3 個的啟用中角色會被自動停用（保留最舊的），且超過 8 小時的會話時長會被調整為 8 小時。

## 常見問題 {#faq}

### 有哪些驗證方式可用？

共有三種方式：PIN 碼（簡易或強化）、OTP（採 TOTP 標準的 2FA 碼）以及 passkey（WebAuthn）。Passkey 提供最高的安全等級（S 級）。

### 在哪裡設定 Authentification Manager？

在 `/settings` 的「防護」分頁中，點擊「Authentification Manager」旁的「設定」，或直接使用 `/auth-settings` 指令。

### 會話到期時會發生什麼事？

我們會自動從成員身上移除受保護的角色。他必須使用 `/auth` 重新驗證才能再次取得，或在會話到期前延長會話。

### 如果我忘記了驗證方式怎麼辦？

在您的 `/auth-profile` 設定檔中，「我忘記了驗證方式」按鈕會完全重設您的帳號：您所有的驗證方式都會被刪除，存取權也會被撤銷。此動作無法復原，且需要完整重新設定。

### Authentification Manager 可以保護多少個角色？

免費版可保護 3 個角色，Premium 版可保護 10 個角色，使用者數量分別為 20 與 50 位。會話的時長，免費版最長 8 小時，Premium 版最長 24 小時。

### 管理者可以修改所有項目嗎？

不行。管理者每次開啟面板時都必須通過驗證，只能管理位階在他之下的角色與使用者，且不能修改伺服器設定。
